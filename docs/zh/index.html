T-VOTE：选民可以在家核验的电子投票机

如何在一台与巴西现行投票机运作方式相同的机器上投票——投票站不联网、有投票站工作人员、早上打印零票报告、结果报告张贴在学校门口——并在之后用自己的电脑核验：你的选票按你的意愿被记录和计入，而无需信任投票机、服务器或选举组织者。

开源学术原型 协议 v4 · 离线投票站 参考实现：TypeScript（Next.js + SQLite）

开放源代码：下载、运行、核验

本文描述的整个系统均已公开。任何人都可以阅读代码，在自己的电脑上运行演示选举，并重复各项核验。

GitHub 代码仓库 下载项目（.zip） 离线验证器（GitHub） 本文在线版

最简单的方式：下载项目（.zip）并解压，然后双击 INICIAR.bat（Windows），或运行 sh iniciar.sh（Linux 和 macOS）。如果电脑上没有 Node.js，它会自动下载，安装所有依赖，并在浏览器中打开系统。如果 Windows 对该文件发出警告，请点击更多信息 → 仍要运行。

使用终端：安装 Node.js 22 或更高版本，然后运行：

cd T-VOTE

这是一个研究原型，而非经过认证的系统。它用于研究和演示一种可验证投票设计。它未经第三方审计，不得用于真实选举。本文示例中的候选人均为虚构；原型只为让演示更逼真才可能加载公开的竞选照片，且没有任何示例偏向某位候选人（在舞弊测试中，受益候选人由随机抽签决定）。

摘要

T-VOTE 是一种端到端可验证（英文 end-to-end verifiable，简称 E2E-V）的电子投票设计。它保留了巴西选民熟悉的流程，并增加了三项任何人都能在家完成的核验，只需一个开源程序和一份公开的选举副本：

  • 我的选票：回执上印的代码会指向你所在投票站公开列表中的加密选票，并显示投票机当时展示的同样两张图片。这证明选票已被记录并进入计票——但不会透露你投给了谁。
  • 我的测试：如果你在投票机上按了 TESTAR（测试），回执上会印有这张测试选票的密钥。在家里，电脑会重新计算并显示其中装的是哪位候选人。如果投票机撒谎，它签名的那张纸就是证据。
  • 我所在投票站的报告：张贴在学校门口的结果报告带有一个代码；公布的报告必须具有相同的代码和相同的数字，而这些数字必须与密码学计票结果一致。

其底层是成熟的密码学原语：基于 ristretto255 群的同态 ElGamal 加密、零知识证明、用于匿名凭证的盲签名、Ed25519 签名，以及一条带签名的区块链。计票由三位密钥保管人（trustees）完成，他们只能解密每个投票站选票的总和，永远无法解密单张选票。本文先用通俗语言解释系统，再逐屏展示原型，然后深入技术细节，最后列出针对系统进行的渗透测试和全部参考文献。

第一部分

写给所有人

不涉及数学：你在投票机上做什么、带什么回家、能核验什么。

1. 一句话说清思路

今天投票时，你必须相信投票机记录了你输入的号码，并且你所在投票站的总数计算无误。现行投票机有许多控制措施来赢得这种信任，但选民本人无法核验自己的选票。

在 T-VOTE 中，投票机仍然放在房间角落、不联网，你按的仍是同样的按键。区别在于：它在知道你要做什么之前，就对自己记录的内容作出承诺，之后再留下可供你在家核验的痕迹。如果它作弊，作弊就会暴露；如果负责汇总选票的机构作弊，同样会暴露。即便如此，任何人——包括你自己——都无法向他人证明你投给了谁。正是这一点防止了买票。

2. 选举日当天

一切都在投票站进行，和今天一样。投票机和投票站工作人员的终端只彼此通信；两者都不连接互联网。

  1. 工作人员核对证件并解锁投票机

    和今天一样。投票机只收到一个“可以投票”——它永远不知道你的名字。

  2. 你输入号码并看到照片

    屏幕显示候选人的姓名、政党和照片。投票机会将照片与选举前公布的指纹进行比对，任何人都无法替换照片。

  3. 你按下 CONFIRMA，出现两张图片和一个代码

    例如：🍄 蘑菇 和 🦴 骨头，以及代码 010 0123 J7K6T。每张图片在文字上方都有图画，方便不识字的人。请记住这两张图片；代码会被打印出来。

  4. 现在选择一个按键

    CONFIRMA（确认）记录选票。TESTAR（测试）打开这张选票，让你看到投票机记录了什么（这张选票作废，你无需重新输入即可再投一次）。CORRIGE（更正）返回重新选择。

  5. 只打印一张纸

    回执上有选票代码、一个 8 位的“校验码”和两张图片的名称。如果你做了测试，同一张纸上还会印有测试内容：投票机声称找到的候选人、测试代码以及这张测试选票的密钥。

    在没有打印机的第一阶段，回执可以以工作人员终端屏幕上的二维码形式交付：选民走出投票间后用手机拍下二维码（第 15 节）。

为什么要测试？当你按下 TESTAR 时，投票机已经显示了这张选票的代码和图片——它在不知道你要投票还是测试之前就作出了承诺。如果它经常记录与显示不同的候选人，每一位做测试的选民都是一次抓住它的机会。你甚至可以输入一个你不打算投的候选人号码来测试。

一天结束时

工作人员关闭投票站，投票机像今天一样打印结果报告（BU，boletim de urna），列出每位候选人的票数。一份张贴在学校门口。新增的是BU 代码（例如 0d94 dbf4 9855 15b1），它唯一标识这份报告。随后，投票站的文件（“介质”）被送到选举机构，由其核查一切后发布到任何人都能下载的区块链上。

3. 在家：三项核验

投票站数据公布后，你可以通过选举网站、一个离线可用的单一文件或命令行程序进行核验。三者使用同一份开放源代码，所有计算都在你的电脑上完成。

我的选票

输入回执上的代码。应当出现你在投票机上看到的同样 2 张图片，以及与纸上相同的校验码。

证明：你的选票在你所在投票站的公开列表中，有效且已被计入。

我的测试

粘贴回执上的“投票机测试”部分。电脑用纸上的密钥重新加密每位候选人，找出其中装的是谁。

证明：投票机说了真话——或者撒了谎，而它在纸上的签名会证明这一点。

投票站的 BU

输入选区和投票站。BU 代码和公布的数字必须与学校门口那张纸上的一致。

证明：在数据离开学校之后，没有人调换你的投票站。

一个真实例子，来自系统试运行中对两次测试的核验：第一次测试中投票机声明号码 80，在家复算结果为 80；第二次声明 27，结果为 27；两份声明都带有投票机的有效签名。结论：“投票站 001-0001 的投票机通过了你的 2 次测试”。

4. 为什么没人能从纸上知道你投给了谁

  • 代码和图片并非来自选票内容。它们来自投票机对一段密文的签名，而每张选票的密文都不同。两位投给同一候选人的选民得到的代码彼此毫无关联。你可以公开说“我的图片是 🌻 向日葵和 ☄️ 彗星”，而不会泄露任何信息。
  • 投下的选票永远不会被打开。每张选票有自己的密钥；投下选票的密钥在同一时刻于投票机内销毁。公开存在的只有密文。
  • 只打开总和。三位密钥保管人各持一部分，共同解密的只是每个投票站的总数。任何一人单独都打不开任何东西。
  • 测试不是选票。测试选票会作废。展示测试并不能证明你的选票，因为你可以测试一位候选人，却投给另一位。
  • 没有时间，也没有顺序。系统不保存选票到达的顺序或每张选票的时间。正是这类信息，使研究人员在 2012 年的一次公开测试中重建了当时巴西投票机的选票顺序。

5. 如果有人作弊会怎样

我们以多种方式故意攻击了系统。下表列出每种作弊由谁发现：

作弊方式谁会发现
投票机记录的候选人与显示的不同，并在测试中撒谎做过测试的选民，在家用纸上的密钥发现
投票机显示你的代码，却记录了另一张选票选民在“我的选票”中发现：其代码在投票站中不存在
投票机打印假密钥，或让测试选票消失做过测试的选民：密钥打不开选票，或测试未被公布
有人篡改数据库中的选票任何审计者：签名不再吻合
选举机构删掉一张选票或修改结果任何审计者：投票机签名或计票证明不再吻合
内部人员利用从投票机中提取的密钥重做整个投票站该投票站的选民（其代码消失）以及贴在学校门口的 BU
有人让整个投票站消失纸质 BU 和该投票站的选民

结论：数学、纸张和选民相互补充。三者中任何一个单独都无法发现所有问题——合在一起，覆盖了所测试的全部舞弊方式。

6. 常见问题

投票机难道不能干脆撒谎显示“核验通过”吗？

可以，所以真正有效的核验是在投票机之外进行的。被篡改的投票机能在自己的屏幕上撒谎，却无法让你电脑的计算得出不同结果：它在不知道你是否会测试之前就对选票作出了承诺，而它打印的密钥只能打开那一张选票。

核验需要懂密码学吗？

不需要。你输入代码，看图片是否相同；如果做过测试，就粘贴测试文本。结果会显示为“你的选票在其中”“投票机是诚实的”或“舞弊”。

有人能强迫我出示回执来证明我的投票吗？

可以要求，但回执什么也证明不了：代码不指向候选人，测试针对的是一张已作废的选票。想买票的人得不到任何保证。

如果我弄丢了回执呢？

你的选票照常计入。你只是失去了核验它的能力。投票站的总数仍然可以由任何人审计。

这条区块链是加密货币吗？

不是。它是一个公开登记簿，每一页都指向前一页并由选举机构签名。没有挖矿，也没有货币：它只是让任何人都能确认公布的内容没有被改动的一种方式。

如果投票站没有打印机呢？

投票后，回执可以以二维码形式显示在工作人员终端的屏幕上。选民走出投票间后用手机拍下二维码。内容与纸质回执相同，并由投票机签名，因此终端无法在不被发现的情况下篡改它。没有手机的人可以要求打印版。

测试投票机会拖慢排队吗？

只需几秒钟。测试选票当场打开；要真正投票，只需再按一次 CONFIRMA——无需重新输入号码。

B. 选举之前

选举机构创建选举并录入候选人。每位候选人的照片通过哈希值封存在创世区块中，投票机会拒绝被替换的照片。三位密钥保管人各自在自己的浏览器中生成密钥份额。三份都公布后，选举开放，投票机即可接受装载。

  • BU 代码：签名后 BU 的哈希值开头部分。公布的 BU 必须具有相同的代码。

第三部分

深入原理

7. 架构

8.1 原语

8.2 选票

设有 k 个选项（候选人、空白票和无效票），选票加密一个向量：所选选项为 1，其余为 0。对每个选项 i：

a_i = g^(r_i) b_i = g^(m_i) · h^(r_i) m_i ∈ {0, 1}, Σ m_i = 1

h 是三位保管人的联合公钥。每一对 (ai, bi) 都附有其加密的是 0 或 1 的证明，选票还附有总和恰好为 1 的证明——且不透露是哪个选项。选票的追踪码是所有密文的 SHA-256。

选票的密钥

每张选票都有一个来自投票机 CSPRNG 的 128 位种子，所有随机数都由它派生：

r_i = H("T-VOTE/aleatoriedade/v1", [种子, 选举哈希, i]) mod L

对于投下的选票，种子在投票瞬间被销毁。对于测试选票，种子会被公开、发布在 BU 中并印在回执上：有了它，任何电脑都能重算每个可能选项的密文，找出被加密的是哪一个。

8.3 匿名凭证

工作人员放行后，投票机生成一个临时 Ed25519 密钥对，并请求工作台终端对公钥进行盲签名。工作台在看不到签名内容的情况下签名，只把计数器加 1，该数字作为投票人数印在 BU 上。选票用这张凭证签名，而作废标识（nullifier，即凭证密钥的 SHA-256）防止同一凭证投票两次。工作台和名册都无法把凭证与选民联系起来。

8.4 封印、代码、图片与校验码

选票一经封存，投票机便用自己的密钥为其加上封印。封印是确定性的（Ed25519）：

封印 = Ed25519(投票机密钥, SHA-256("T-VOTE/selo/v1|" ‖ {选举, 追踪码, 投票站})) v = SHA-256("T-VOTE/verificacao/v1|" ‖ 封印) 图片 = 图片表[v[0]], 图片表[v[1]] 16 位（256 张图片） 代码 = 选区 ‖ 投票站 ‖ base32(v[2..6] 中的 25 位) 25 个随机位 校验码 = base32(v[6..11] 中的 40 位) 40 位

代码使用 Crockford base32（不含 I、L、O、U）；读取时 O 视为 0，I/L 视为 1。它在投票站内唯一，前缀中的投票站使其在整个选举中唯一。256 张图片经过挑选，都易于画出，没有只差一个字母的组合，也不含政治、宗教或武器内容。

为什么需要校验码。仅凭 2 张图片只有 16 位：在一次试验中，一台被篡改的投票机在不到一千次加密内，就找到了两张图片相同的选票（每位候选人各一张）——它可以在测试时打开其中一张，而投出另一张。加上代码后（41 位），找到同样的一对约需 220 次加密，仍在有准备的投票机能力范围之内。在决定前打印的校验码将承诺提高到 81 位：同样的攻击需要当场进行约 240 次加密，这是不可行的。

8.5 投票机测试（Benaloh 挑战）

看到承诺后，选民可以按下 TESTAR。投票机公开种子，为 BU 保留已打开的选票，并签署一份声明，写明它声称找到的候选人以及打印的密钥：

声明 = Ed25519(投票机密钥, SHA-256("T-VOTE/declaracao-teste/v2|" ‖ {选举, 投票站, 追踪码, 选项, 种子}))

在家里，验证器用纸上的种子重新加密每个选项，寻找唯一一个能精确重现该代码下封存密文的选项。如果它不是声明的那个，就说明投票机撒了谎，而签名使其成为可转交的证据。如果有人篡改纸张，签名就不再吻合——伪造的纸张无法诬陷一台诚实的投票机。

8.6 零票报告与结果报告

两者都是由投票机签名的规范 JSON 文档：

  • 零票报告：选举、投票站、投票机密钥、工作台密钥、软件哈希、存储中的选票数（零）以及开站时间。
  • BU：指向零票报告的哈希，包含投票人数（工作台计数器）、按追踪码排序的全部选票和测试选票、各选项的明文计数（即打印内容）以及密文的同态聚合值。

印在纸上的 BU 代码是文档哈希的前 16 个十六进制字符。

8.7 按投票站计票

选举密钥是三位保管人密钥的乘积。对每个投票站 s 和选项 j，设聚合值为 (Asj, Bsj)：

D_sj,t = A_sj^(x_t) （附 Chaum-Pedersen 证明；上下文包含投票站） g^(m_sj) = B_sj / (D_sj,1 · D_sj,2 · D_sj,3) → 在 [0, 选票数] 中搜索得到 m_sj

解密前，每位保管人都会审计数据包并重新计算聚合值；对于不是自己重新计算出的总和，一律拒绝解密。逐个投票站解密，使得每份打印的 BU 都能与密码学计票结果比对。

11. 全民审计

审计者只拿到公开数据包（区块链），并重做 22 项检查：

  1. 链的完整性（每个区块的哈希和链接）
  2. 每个区块上的公告板签名
  3. 选举清单（创世区块）和协议版本
  4. 阶段顺序
  5. 附 Schnorr 证明的保管人密钥
  6. 全国零票报告和联合密钥
  7. 投票机装载：自有密钥、无重复、软件与创世区块一致、介质之后无装载
  8. 介质由装载的投票机签名、零票报告为零、每个投票站一份介质
  9. 选票无到达顺序和时间（字段精确、按追踪码排序）
  10. 投票站工作台签发的有效匿名凭证
  11. 每张选票的签名
  12. 零知识证明
  13. 重新计算的追踪码和作废标识
  14. 代码、图片和校验码由封印派生；代码唯一
  15. 一张凭证，一张选票
  16. 测试选票与公开的种子吻合
  17. 选票数 ≤ 投票人数；BU 计数之和等于选票数
  18. 各投票站的同态总和
  19. 关闭记录准确列出已接收的投票站和缺少介质的投票站
  20. 每位保管人逐站的部分解密及其证明
  21. 打印的 BU = 密码学计票结果
  22. 公布结果 = 重新计算的结果（按投票站及总计）

软件被篡改的投票机

七台实验室投票机模拟在装载前被替换的程序。它们都向选民显示其输入的内容，都声称软件一致，而且每一台的 BU 都通过了数学审计——因为投票机在 BU 中计入的正是它实际加密的内容。每一种情况下，舞弊都在家中被发现：

被篡改的软件在家核验的结果
转移全部选票并在测试中撒谎纸上写 29；密钥复算出 21 → 舞弊，签名有效
转移一半选票3 次测试中有 2 次发现转移 → 舞弊
只转移某一位候选人的选票测试了受害候选人；密钥复算出另一人 → 舞弊
把选票变成无效票测试选票为无效票 → 舞弊
在测试中打印假密钥密钥打不开封存的选票 → 舞弊
让测试选票消失测试不在公布的 BU 中 → 舞弊
显示你的代码却记录另一张选票（测试时诚实）选票代码在 BU 中不存在 → 舞弊（在“我的选票”中发现）

数学看不见意图。一台加密了错误候选人的投票机，产生的是一张完全有效的选票。只有选民知道自己输入了什么——因此在投票机之外核验的测试不可或缺，这也是系统把数学审计与纸张和选民结合起来的原因。

13. 投票保密与 2012 年 TPS 的教训

在 2012 年巴西投票机公开安全测试（TPS）中，研究人员证明可以重建当时投票机所记录选票的顺序，因为其洗牌使用了以时间为种子的非密码学随机数生成器。T-VOTE 从多个层面应对：

  • 没有需要设定种子的洗牌：BU 按追踪码顺序列出选票，即随机密文的哈希顺序。
  • 投票机存储是一张没有顺序编号的表，按（投票机，追踪码）索引：保存的是哈希顺序，而非到达顺序。
  • 没有逐票带时间的记录；SQLite 日志采用 DELETE 模式并启用 secure_delete，抹去可能残留的数据。
  • 名册不记录到场顺序，工作台进行盲签名。
  • 每张投下选票的密钥在投票后即不复存在。

在一项每位候选人 160 张选票的统计测试中，第一张图片为“奇数”的比例在一位候选人的选票中是 49%，在另一位的选票中是 50%，符合与选票内容无关的取值的预期。

14. 局限与后续工作

说明尚未解决的问题，本身就是安全的一部分。

  • 针对被篡改投票机的保密性。投票机能看到选票，和现行投票机一样。被篡改后，它可以挑选随机数，使图片“编码”候选人——这是一个在实验室中演示过的隐蔽信道（20 张选票全部泄露，每张最多只需几十次加密）。完整性不依赖于信任投票机；但针对它的保密性依赖。后续工作：由第二台独立设备提供随机性，并在封印前重新加密。
  • 持有投票机和工作台密钥的内部人员可以伪造一个在数学上完美的投票站。能发现它的是选民和纸质 BU；因此纸张和监票人的照片仍然不可或缺。
  • 选民之间的碰撞攻击（clash）：被篡改的投票机可能向两位选民展示同一张选票。每个人单独都能找到“自己的”代码；只有比对回执才能发现。
  • 测试是概率性的，取决于有多少选民做测试。
  • 三位保管人缺一不可。生产环境中：采用分布式密钥生成的 t-of-n 门限方案。
  • 凭证使用 RSA-FDH。生产环境中：标准化盲签名（RFC 9474）。
  • 密钥存放在软件中。生产环境中：硬件模块（HSM/TPM）、度量启动和可复现构建。
  • 现场胁迫（有人在投票间内、拍摄屏幕）超出了密码学的能力范围。
  • 代码未经第三方审计。

15. 无打印机部署：以二维码交付回执

每台投票机配一台热敏打印机（以及纸张、维护和物流）是本设计中最昂贵的部分。为了在不承担这笔成本的情况下起步，回执可以以数字形式在投票后于工作人员终端上交付：

  1. 选民按上文所述在投票机上投票（如愿意也可测试）。投票机照常在自己的屏幕上显示图片、代码和校验码。
  2. 选民确认后，投票机通过其放行时已在使用的同一本地信道，将回执发送到工作人员终端，无需联网。
  3. 选民走出投票间，终端在朝向选民的屏幕区域显示包含回执的二维码。选民用手机拍下二维码，下一位选民被放行时屏幕即被清空。
  4. 在家里，核验页面或离线验证器读取二维码，完成与纸质回执相同的核验：选票、测试和 BU。

二维码里装了什么

与纸上完全相同的内容：选票代码、校验码、图片名称以及投票机对回执的签名。每次测试还包括声明的候选人、代码、测试选票的密钥和签名的声明。含一两张测试选票时大约是几百个字符，可以放进一个中等大小、易于从屏幕读取的二维码。如果二维码是核验页面的网址，数据必须放在 #（URL 片段）之后，浏览器不会把这部分发送给服务器： 

https://<核验页面>/verificar#v=1&c=0100123WGFTT&k=9RD2RJJP&s=…&t=…

为什么放在工作人员终端，而不是投票间里

  • 法律禁止在投票间内使用手机。巴西第 9.504/1997 号法律第 91-A 条唯一款禁止携带手机和照相机进入投票间。二维码显示在终端上，选民只在离开投票间后才使用手机。
  • 终端本来就存在。无需新硬件，只需软件。部署成本接近于零。
  • 纸张仍然可用。两种方式可以并存：默认使用二维码，为提出要求或没有手机的人提供纸质回执。这使得可以逐个投票站逐步过渡。

对安全性有什么影响

问题分析
工作人员终端能显示伪造的二维码吗？不被发现是做不到的。回执和测试声明都由投票机用装载时公布的密钥签名，验证器会核验这些签名。被篡改或调换的代码无法吻合：图片与投票机屏幕上显示的不同，或者签名验证失败。
工作人员会看到回执吗？可能会，但这不会泄露选票：代码和图片与候选人无关。测试部分显示的是被测试的候选人，属于一张已作废的选票。为保持隐私，二维码显示在朝向选民的区域，并在下一次放行时消失。
如果终端不显示二维码呢？选民只是失去了事后核验的机会。选票已经投出并被计入。系统性地拒绝交付回执是显而易见的，监票人可以记录在案。
对抗被篡改投票机的锚点仍然是投票机在决定前于自己屏幕上显示的内容：2 张图片、代码和校验码。选民核对二维码中的值是否一致。这保持了第 8.4 节中的 81 位承诺。
买卖选票与纸质回执相同：二维码无法证明此人投给了谁。
包容性并非每位选民都有带摄像头的手机。因此应保留按需打印，即使每个投票地点只有少量打印机。

原型中尚未实现。目前原型在纸上打印回执（在屏幕上模拟）。工作人员终端上的二维码是针对第一阶段部署的提案。密码学部分不变：改变的只是回执的交付方式。

16. 如何复现

原型在单台电脑上运行，运行期间不访问互联网。代码：github.com/tauz-hub/T-VOTE。

前提条件：Node.js 22 或更高版本。如果缺少 Node.js，启动脚本 INICIAR.bat 和 iniciar.sh 会自动下载（见代码与下载）。

git clone https://github.com/tauz-hub/T-VOTE.git
cd T-VOTE
npm install
npm run dev               # http://127.0.0.1:3000
npm run teste             # 内存中的协议：审计器、在家复算的测试以及 14 种攻击
npm run teste:invasao     # 通过真实模块进行完整选举 + 渗透测试报告
npm run validador         # 生成离线验证器（单个 HTML 文件）
npm run auditar -- pacote.json
npm run verificar -- pacote.json <代码> ["测试密钥"]
npm run verificar -- pacote.json --bu 010-0123

演示流程

  1. Admin → 选举：创建选举（候选人可编辑）。
  2. Trustees：生成三把密钥；然后在 Admin 中点击开放选举。
  3. 登记：生成虚构选民。
  4. 工作人员：在不同窗口中打开终端和投票机。在投票机上用键盘完成安装（选区和投票站），按 CONFIRMA 进行装载。在终端上开放投票站。
  5. 投票：放行一位选民，输入号码，按 TESTAR，再按 CONFIRMA；保留回执。
  6. 关闭：关闭投票站（BU）并传送介质；在 Admin 中停止接收；在 Trustees 中解密。
  7. 在家：核验选票（代码）、核验测试（粘贴回执）、投票站报告和审计。
  8. 舞弊：Admin → 攻击实验室 → 创建 7 台示例投票机 → 全部模拟并传送 → 在家核验。

为了不依赖你下载的验证器文件，请从源代码重新生成并比较 SHA-256：构建是确定性的。完整规范——格式、哈希域、检查项和 API——随代码一同提供，一个独立实现（例如用 Python）应当接受原型的数据包，并拒绝同样的篡改。
