T-VOTE: ein Wahlgerät, das Wähler zu Hause überprüfen können

Wie man an einem Gerät wählt, das wie das heutige brasilianische funktioniert — Wahllokal ohne Internet, Wahlhelfer, Nullprotokoll am Morgen, Ergebnisprotokoll an der Schultür — und danach am eigenen Computer überprüft, dass die eigene Stimme so erfasst und gezählt wurde, wie man sie abgegeben hat, ohne dem Gerät, dem Server oder den Wahlveranstaltern vertrauen zu müssen.

Akademischer Open-Source-Prototyp Protokoll v4 · Wahllokal offline Referenzimplementierung: TypeScript (Next.js + SQLite)

Offener Quellcode: herunterladen, ausführen, prüfen

Das gesamte hier beschriebene System ist veröffentlicht. Jeder kann den Code lesen, die Demowahl auf dem eigenen Computer ausführen und die Prüfungen wiederholen.

Dies ist ein Forschungsprototyp, kein zertifiziertes System. Er dient dazu, ein verifizierbares Wahlverfahren zu untersuchen und vorzuführen. Er wurde nicht von Dritten geprüft und darf nicht bei echten Wahlen eingesetzt werden. Die Kandidaten in den Beispielen dieses Dokuments sind fiktiv; der Prototyp kann öffentliche Wahlkampffotos nur laden, um die Demo realistisch zu machen, und kein Beispiel bevorzugt einen Kandidaten (in den Betrugstests wird der begünstigte Kandidat ausgelost).

Zusammenfassung

T-VOTE ist ein Entwurf für elektronische Wahlen, der Ende-zu-Ende-verifizierbar ist (englisch end-to-end verifiable, E2E-V). Er behält den Ablauf bei, den brasilianische Wähler kennen, und ergänzt drei Prüfungen, die jeder zu Hause durchführen kann — mit einem Open-Source-Programm und einer öffentlichen Kopie der Wahl:

  • Meine Stimme: Der Code auf dem Beleg führt zu Ihrer verschlüsselten Stimme in der öffentlichen Liste Ihres Wahllokals, mit denselben zwei Bildern, die das Gerät gezeigt hat. Das beweist, dass die Stimme erfasst und mitgezählt wurde — ohne zu verraten, wen Sie gewählt haben.
  • Mein Test: Wenn Sie am Gerät TESTAR (testen) gedrückt haben, enthält der Beleg den Schlüssel dieses Teststimmzettels. Zu Hause rechnet der Computer nach und zeigt, welcher Kandidat darin war. Hat das Gerät gelogen, ist das von ihm signierte Papier der Beweis.
  • Das Protokoll meines Wahllokals: Das an der Schultür ausgehängte Ergebnisprotokoll hat einen Code; das veröffentlichte Protokoll muss denselben Code und dieselben Zahlen haben, und die Zahlen müssen mit der kryptografischen Auszählung übereinstimmen.

Darunter liegen bewährte kryptografische Bausteine: homomorphe ElGamal-Verschlüsselung über der Gruppe ristretto255, Zero-Knowledge-Beweise, blinde Signaturen für anonyme Berechtigungsnachweise, Ed25519-Signaturen und eine signierte Blockkette. Die Auszählung erfolgt durch drei Schlüsselverwahrer (Trustees), die nur die Summe der Stimmen eines Wahllokals entschlüsseln können, nie eine einzelne Stimme. Dieses Dokument erklärt das System zuerst in Alltagssprache, zeigt dann jeden Bildschirm des Prototyps und geht schließlich ins technische Detail; am Ende stehen die durchgeführten Penetrationstests und alle Quellen.

Teil I

Für alle

Ohne Mathematik: was Sie am Gerät tun, was Sie mit nach Hause nehmen und was Sie prüfen können.

1. Die Idee in wenigen Worten

Wenn Sie heute wählen, müssen Sie darauf vertrauen, dass das Gerät die eingegebene Nummer gespeichert hat und dass die Summe Ihres Wahllokals richtig gebildet wurde. Das heutige Gerät hat viele Kontrollen, um dieses Vertrauen zu verdienen, aber der einzelne Wähler kann seine eigene Stimme nicht überprüfen.

Bei T-VOTE steht das Gerät weiterhin in der Ecke des Raums, ohne Internet, und Sie drücken weiterhin dieselben Tasten. Der Unterschied: Es legt sich fest, was es gespeichert hat, bevor es weiß, was Sie tun werden, und hinterlässt danach Spuren, die Sie zu Hause prüfen. Betrügt es, fällt der Betrug auf. Betrügt die Stelle, die die Stimmen zusammenzählt, fällt das ebenfalls auf. Und trotzdem kann niemand — auch Sie nicht — einer anderen Person beweisen, wen Sie gewählt haben. Genau das verhindert Stimmenkauf.

2. Am Wahltag

Alles geschieht im Wahllokal, wie heute. Das Gerät und das Terminal des Wahlhelfers sprechen nur miteinander; keines ist mit dem Internet verbunden.

  1. Der Wahlhelfer prüft Ihren Ausweis und gibt das Gerät frei

    Wie heute. Das Gerät erhält nur ein „darf wählen“ — Ihren Namen erfährt es nie.

  2. Sie tippen die Nummer und sehen das Foto

    Der Bildschirm zeigt Name, Partei und Foto des Kandidaten. Das Gerät prüft das Foto selbst gegen einen vor der Wahl veröffentlichten Fingerabdruck, damit niemand es austauschen kann.

  3. Sie drücken CONFIRMA und es erscheinen zwei Bilder und ein Code

    Zum Beispiel: 🍄 PILZ und 🦴 KNOCHEN sowie der Code 010 0123 J7K6T. Jedes Bild hat über dem Wort eine Zeichnung für Menschen, die nicht lesen können. Merken Sie sich die Bilder; der Code wird gedruckt.

  4. Jetzt wählen Sie eine Taste

    CONFIRMA (bestätigen) speichert die Stimme. TESTAR (testen) öffnet diesen Stimmzettel, damit Sie sehen, was das Gerät gespeichert hat (er wird ungültig und Sie wählen erneut, ohne neu zu tippen). CORRIGE (korrigieren) geht zurück, um einen anderen zu wählen.

  5. Es kommt ein einziger Zettel heraus

    Der Beleg enthält den Stimmcode, einen 8-stelligen „Prüfcode“ und die Namen der beiden Bilder. Wenn Sie getestet haben, steht auf demselben Zettel der Test: der Kandidat, den das Gerät gefunden haben will, der Testcode und der Schlüssel dieses Teststimmzettels.

    In einer ersten Phase ohne Drucker kann der Beleg als QR-Code auf dem Bildschirm des Wahlhelfer-Terminals ausgegeben werden: Der Wähler verlässt die Kabine und fotografiert den Code mit dem Handy (Abschnitt 15).

Warum testen? Wenn Sie TESTAR drücken, hat das Gerät Code und Bilder dieses Stimmzettels bereits gezeigt — es hat sich festgelegt, bevor es wusste, ob Sie wählen oder testen. Speichert es oft einen anderen Kandidaten als den angezeigten, ist jeder testende Wähler eine Chance, es zu ertappen. Sie können sogar mit der Nummer von jemandem testen, den Sie nicht wählen werden.

Am Ende des Tages

Der Wahlhelfer schließt das Wahllokal, und das Gerät druckt wie heute das Ergebnisprotokoll (BU, boletim de urna) mit den Stimmen jedes Kandidaten. Ein Exemplar kommt an die Schultür. Neu ist der BU-Code (zum Beispiel 0d94 dbf4 9855 15b1), der genau dieses Protokoll identifiziert. Danach wird die Datei des Wahllokals (das „Medium“) zur Wahlbehörde gebracht, die alles prüft und auf einer Blockkette veröffentlicht, die jeder herunterladen kann.

3. Zu Hause: die drei Prüfungen

Sobald das Wahllokal veröffentlicht ist, können Sie mit der Website der Wahl prüfen, mit einer einzelnen Datei, die offline funktioniert, oder mit einem Kommandozeilenprogramm. Alle drei nutzen denselben offenen Quellcode und rechnen vollständig auf Ihrem Computer.

Meine Stimme

Geben Sie den Code vom Beleg ein. Es müssen dieselben 2 Bilder wie am Gerät und derselbe Prüfcode wie auf dem Papier erscheinen.

Beweist: Ihre Stimme steht in der öffentlichen Liste Ihres Wahllokals, ist gültig und wurde mitgezählt.

Mein Test

Fügen Sie den Teil „GERÄTETEST“ des Belegs ein. Der Computer verschlüsselt jeden Kandidaten mit dem Schlüssel vom Papier neu und findet den, der darin war.

Beweist: Das Gerät hat die Wahrheit gesagt — oder gelogen, und seine Signatur auf dem Papier zeigt es.

Das BU des Wahllokals

Geben Sie Zone und Lokal ein. BU-Code und veröffentlichte Zahlen müssen mit dem Papier an der Schultür übereinstimmen.

Beweist: Niemand hat Ihr Wahllokal ausgetauscht, nachdem es die Schule verlassen hat.

Ein echtes Beispiel, aus der Prüfung zweier Tests bei einem Probelauf des Systems: Der erste Test, bei dem das Gerät die Nummer 80 erklärte, wurde zu Hause nachgerechnet und ergab 80; der zweite, erklärt 27, ergab 27; beide Erklärungen trugen eine gültige Signatur des Geräts. Ergebnis: „Das Gerät im Wahllokal 001-0001 hat Ihre 2 Tests bestanden“.

4. Warum niemand Ihre Stimme am Papier erkennt

  • Code und Bilder stammen nicht aus der Stimme. Sie entstehen aus einer Signatur des Geräts über eine Verschlüsselung, die bei jedem Stimmzettel anders ist. Zwei Wähler, die denselben Kandidaten wählen, erhalten Codes ohne jeden Zusammenhang. Sie können öffentlich sagen „meine Bilder waren 🌻 SONNENBLUME und ☄️ KOMET“, ohne etwas zu verraten.
  • Die abgegebene Stimme wird nie geöffnet. Jeder Stimmzettel hat einen eigenen Schlüssel; der Schlüssel der abgegebenen Stimme wird im selben Moment im Gerät vernichtet. Öffentlich existiert nur der Geheimtext.
  • Nur die Summe wird geöffnet. Drei Schlüsselverwahrer mit je einem Teil entschlüsseln gemeinsam nur die Gesamtsumme jedes Wahllokals. Keiner von ihnen kann allein etwas öffnen.
  • Der Test ist nicht die Stimme. Der Teststimmzettel ist ungültig. Den Test zu zeigen beweist die Stimme nicht, denn man kann einen Kandidaten testen und einen anderen wählen.
  • Keine Uhrzeit und keine Reihenfolge. Nichts speichert die Reihenfolge, in der die Stimmen eingingen, oder deren Uhrzeit. Genau das erlaubte es bei einem öffentlichen Test 2012, die Reihenfolge der Stimmen im damaligen brasilianischen Gerät zu rekonstruieren.

Das System wurde absichtlich auf viele Arten angegriffen. Diese Tabelle zeigt, wer welchen Betrug bemerkt:

Die Lehre: Mathematik, Papier und Wähler ergänzen einander. Keiner der drei erkennt allein alles — zusammen decken sie die getesteten Betrugsarten ab.

6. Häufige Fragen

Könnte das Gerät nicht einfach lügend „Prüfung OK“ anzeigen?

Doch, und deshalb zählt nur die Prüfung außerhalb des Geräts. Ein manipuliertes Gerät kann auf dem eigenen Bildschirm lügen, aber es kann nicht bewirken, dass die Rechnung Ihres Computers ein anderes Ergebnis liefert: Es hat sich auf den Stimmzettel festgelegt, bevor es wusste, ob Sie testen, und der gedruckte Schlüssel öffnet nur diesen Stimmzettel.

Muss ich Kryptografie verstehen, um zu prüfen?

Nein. Sie geben den Code ein, sehen nach, ob die Bilder gleich sind, und fügen, falls Sie getestet haben, den Testtext ein. Die Antwort lautet „Ihre Stimme ist da“, „das Gerät war ehrlich“ oder „Betrug“.

Kann mich jemand zwingen, den Beleg vorzuzeigen, um meine Stimme zu beweisen?

Verlangen kann man es, aber der Beleg beweist nichts: Der Code verrät keinen Kandidaten, und der Test betrifft einen ungültigen Stimmzettel. Wer Stimmen kaufen will, bekommt keinerlei Garantie.

Und wenn ich den Beleg verliere?

Ihre Stimme wird ganz normal gezählt. Sie verlieren nur die Möglichkeit, sie zu prüfen. Die Summe des Wahllokals bleibt für alle prüfbar.

Ist die Blockkette eine Kryptowährung?

Nein. Sie ist ein öffentliches Register, in dem jede Seite auf die vorherige verweist und von der Wahlbehörde signiert ist. Es gibt kein Mining und keine Währung: Es ist nur ein Weg, wie jeder prüfen kann, dass niemand das Veröffentlichte verändert hat.

Und wenn das Wahllokal keinen Drucker hat?

Der Beleg kann nach der Stimmabgabe als QR-Code auf dem Bildschirm des Wahlhelfer-Terminals ausgegeben werden. Der Wähler, bereits außerhalb der Kabine, fotografiert den Code mit dem Handy. Der Inhalt ist derselbe wie auf Papier und vom Gerät signiert, sodass das Terminal ihn nicht unbemerkt ändern kann. Wer kein Handy hat, kann die gedruckte Version verlangen.

Verlängert das Testen die Warteschlange?

Um wenige Sekunden. Der Teststimmzettel wird sofort geöffnet, und um tatsächlich zu wählen, drückt man einfach erneut CONFIRMA — ohne die Nummer neu einzugeben.

B. Vor der Wahl

Die Wahlbehörde legt die Wahl mit den Kandidaten an. Das Foto jedes Kandidaten wird per Hash im Genesis-Block versiegelt, und das Gerät lehnt ein ausgetauschtes Foto ab. Die drei Trustees erzeugen jeweils ihren Schlüsselanteil im eigenen Browser. Sind alle drei veröffentlicht, wird die Wahl eröffnet und die Geräte können geladen werden.

7.3 Phasen

GENESE → CHAVE_TRUSTEE ×3 → ABERTURA → (CARGA | SECAO)* → ENCERRAMENTO → DECRIPTACAO_PARCIAL ×3 → RESULTADO

Jeder Block enthält den Hash des vorherigen und ist mit dem Ed25519-Schlüssel der Tafel signiert, der im Genesis-Block veröffentlicht wird. Genesis veröffentlicht auch die Optionen (mit dem SHA-256 jedes Fotos) und den Hash der im Wahllokal laufenden Software.

8.2 Der Stimmzettel

Bei k Optionen (Kandidaten, leer und ungültig) verschlüsselt der Stimmzettel einen Vektor mit 1 bei der gewählten Option und 0 bei den übrigen. Für jede Option i:

a_i = g^(r_i) b_i = g^(m_i) · h^(r_i) m_i ∈ {0, 1}, Σ m_i = 1

h ist der gemeinsame öffentliche Schlüssel der drei Trustees. Jedes Paar (ai, bi) trägt einen Beweis, dass es 0 oder 1 verschlüsselt, und der Stimmzettel trägt einen Beweis, dass die Summe genau 1 verschlüsselt — ohne zu verraten, welche Option. Der Tracker des Stimmzettels ist der SHA-256 aller Geheimtexte.

Der Schlüssel des Stimmzettels

Jeder Stimmzettel hat einen 128-Bit-Seed aus dem CSPRNG des Geräts, und aller Zufall wird daraus abgeleitet:

r_i = H("T-VOTE/aleatoriedade/v1", [Seed, Wahl_Hash, i]) mod L

Beim abgegebenen Stimmzettel wird der Seed im Moment der Abgabe vernichtet. Beim Teststimmzettel wird er offengelegt, im BU veröffentlicht und auf den Beleg gedruckt: Damit rechnet jeder Computer die Geheimtexte jeder möglichen Option nach und findet heraus, welche verschlüsselt wurde.

8.3 Anonymer Berechtigungsnachweis

Nach der Freigabe durch den Wahlhelfer erzeugt das Gerät ein flüchtiges Ed25519-Paar und bittet das Terminal des Wahlvorstands um eine blinde Signatur über den öffentlichen Schlüssel. Der Vorstand signiert, ohne zu sehen, was er signiert, und erhöht nur seinen Zähler, der als Wahlbeteiligung ins BU gedruckt wird. Der Stimmzettel wird mit diesem Nachweis signiert, und der Nullifier (SHA-256 des Nachweisschlüssels) verhindert, dass derselbe Nachweis zweimal wählt. Weder Vorstand noch Verzeichnis können einen Nachweis einem Wähler zuordnen.

8.4 Siegel, Code, Bilder und Prüfcode

Sobald der Stimmzettel verschlossen ist, versiegelt das Gerät ihn mit seinem eigenen Schlüssel. Das Siegel ist deterministisch (Ed25519):

Siegel = Ed25519(Geräteschlüssel, SHA-256("T-VOTE/selo/v1|" ‖ {Wahl, Tracker, Lokal})) v = SHA-256("T-VOTE/verificacao/v1|" ‖ Siegel) Bilder = BILDER[v[0]], BILDER[v[1]] 16 Bit (256 Bilder) Code = Zone ‖ Lokal ‖ base32(25 Bit von v[2..6]) 25 Zufallsbits Prüfcode = base32(40 Bit von v[6..11]) 40 Bit

Der Code nutzt Crockford-Base32 (ohne I, L, O und U); beim Lesen wird O zu 0 und I/L zu 1. Er ist im Wahllokal eindeutig, und das Lokal im Präfix macht ihn in der Wahl eindeutig. Die 256 Bilder wurden so gewählt, dass sie zeichenbar sind, keine Paare sich nur in einem Buchstaben unterscheiden und es keine politischen, religiösen oder Waffen-Inhalte gibt.

Warum es den Prüfcode gibt. Die 2 Bilder allein haben 16 Bit: In einem Versuch fand ein manipuliertes Gerät in weniger als tausend Verschlüsselungen zwei Stimmzettel (je einen pro Kandidat) mit denselben Bildern — und hätte einen im Test öffnen und den anderen abgeben können. Mit Code und Bildern (41 Bit) bräuchte dasselbe Paar etwa 220 Verschlüsselungen, noch immer in Reichweite eines vorbereiteten Geräts. Der vor der Entscheidung gedruckte Prüfcode hebt die Festlegung auf 81 Bit: Derselbe Angriff bräuchte dann etwa 240 Verschlüsselungen in Echtzeit, was nicht machbar ist.

8.5 Gerätetest (Benaloh-Challenge)

Nachdem der Wähler die Festlegung gesehen hat, kann er TESTAR drücken. Das Gerät legt den Seed offen, bewahrt den geöffneten Stimmzettel für das BU auf und signiert eine Erklärung mit dem Kandidaten, den es gefunden haben will, und dem gedruckten Schlüssel:

Erklärung = Ed25519(Geräteschlüssel, SHA-256("T-VOTE/declaracao-teste/v2|" ‖ {Wahl, Lokal, Tracker, Option, Seed}))

Zu Hause verschlüsselt der Validator jede Option mit dem Seed vom Papier neu und sucht die einzige, die die unter diesem Code versiegelten Geheimtexte exakt reproduziert. Ist es nicht die erklärte, hat das Gerät gelogen, und die Signatur macht daraus einen übertragbaren Beweis. Ändert jemand das Papier, passt die Signatur nicht mehr — ein gefälschtes Papier belastet kein ehrliches Gerät.

8.6 Nullprotokoll und Ergebnisprotokoll

Beide sind kanonische JSON-Dokumente, vom Gerät signiert:

  • Nullprotokoll: Wahl, Wahllokal, Geräteschlüssel, Vorstandsschlüssel, Software-Hash, Zahl der Stimmzettel im Speicher (null) und Eröffnungszeit.
  • BU: verweist auf den Hash des Nullprotokolls und enthält die Wahlbeteiligung (Zähler des Vorstands), alle Stimmzettel und Teststimmzettel in Tracker-Reihenfolge, die Klartextzählung pro Option (was gedruckt wird) und das homomorphe Aggregat der Geheimtexte.

Der auf das Papier gedruckte BU-Code sind die ersten 16 Hexadezimalzeichen des Dokument-Hashs.

8.7 Auszählung pro Wahllokal

Der Wahlschlüssel ist das Produkt der Schlüssel der drei Trustees. Für jedes Wahllokal s und jede Option j mit Aggregat (Asj, Bsj):

D_sj,t = A_sj^(x_t) (mit Chaum-Pedersen-Beweis; Kontext enthält das Lokal) g^(m_sj) = B_sj / (D_sj,1 · D_sj,2 · D_sj,3) → m_sj durch Suche in [0, Zahl der Stimmzettel]

Vor dem Entschlüsseln prüft jeder Trustee das Paket und berechnet das Aggregat neu; er weigert sich, etwas anderes zu entschlüsseln als die selbst neu berechnete Summe. Die Entschlüsselung Lokal für Lokal erlaubt es, jedes gedruckte BU mit der kryptografischen Auszählung zu vergleichen.

11. Universelle Prüfung

Der Prüfer erhält nur das öffentliche Paket (die Blockkette) und wiederholt 22 Prüfungen:

  1. Integrität der Kette (Hash und Verkettung jedes Blocks)
  2. Signatur der Tafel auf jedem Block
  3. Wahlmanifest (Genesis) und Protokollversion
  4. Reihenfolge der Phasen
  5. Trustee-Schlüssel mit Schnorr-Beweis
  6. Nationales Nullprotokoll und gemeinsamer Schlüssel
  7. Laden der Geräte: eigener Schlüssel, keiner wiederholt, Software gleich Genesis, kein Laden nach dem Medium
  8. Medien vom geladenen Gerät signiert, Nullprotokoll auf null, ein Medium pro Lokal
  9. Stimmzettel ohne Eingangsreihenfolge und ohne Uhrzeit (exakte Felder, Tracker-Reihenfolge)
  10. Gültige anonyme Nachweise des Vorstands des Lokals
  11. Signatur jedes Stimmzettels
  12. Zero-Knowledge-Beweise
  13. Tracker und Nullifier neu berechnet
  14. Code, Bilder und Prüfcode aus dem Siegel abgeleitet; eindeutige Codes
  15. Ein Nachweis, eine Stimme
  16. Teststimmzettel stimmen mit dem offengelegten Seed überein
  17. Stimmzettel ≤ Beteiligung; die BU-Zählung ergibt die Zahl der Stimmzettel
  18. Homomorphe Summe pro Lokal
  19. Die Schließung listet genau die empfangenen Lokale und die ohne Medium
  20. Teilentschlüsselung jedes Trustees, Lokal für Lokal, mit Beweis
  21. Gedrucktes BU = kryptografische Auszählung
  22. Veröffentlichtes Ergebnis = neu berechnet, pro Lokal und insgesamt

Geräte mit manipulierter Software

Sieben Laborgeräte simulieren vor dem Laden ausgetauschte Programme. Alle zeigen dem Wähler, was er eingegeben hat, alle behaupten, die Software stimme, und das BU aller besteht die mathematische Prüfung — weil das Gerät im BU zählt, was es tatsächlich verschlüsselt hat. In jedem Fall wurde der Betrug zu Hause entdeckt:

Manipulierte SoftwareErgebnis zu Hause

Leitet die Hälfte der Stimmen um2 von 3 Tests entdeckten die Umleitung → Betrug
Leitet nur die Stimmen eines Kandidaten umDer Opfer-Kandidat wurde getestet; der Schlüssel reproduzierte einen anderen → Betrug
Macht Stimmen ungültigDer Teststimmzettel war ungültig → Betrug
Druckt im Test einen falschen SchlüsselDer Schlüssel öffnet den versiegelten Stimmzettel nicht → Betrug

Zeigt Ihren Code und speichert einen anderen Stimmzettel (im Test ehrlich)Der Stimmcode existiert im BU nicht → Betrug (entdeckt unter „Meine Stimme“)

Mathematik sieht keine Absicht. Ein Gerät, das den falschen Kandidaten verschlüsselt, erzeugt einen vollkommen gültigen Stimmzettel. Nur der Wähler weiß, was er eingegeben hat — deshalb ist der außerhalb des Geräts geprüfte Test unverzichtbar, und deshalb verbindet das System die mathematische Prüfung mit dem Papier und dem Wähler.

13. Wahlgeheimnis und die Lehre aus dem TPS 2012

Beim öffentlichen Sicherheitstest (TPS) 2012 des brasilianischen Wahlgeräts zeigten Forschende, dass sich die Reihenfolge der vom damaligen Gerät gespeicherten Stimmen rekonstruieren ließ, weil das Mischen einen nicht-kryptografischen Generator nutzte, der mit der Uhrzeit initialisiert wurde. T-VOTE antwortet auf mehreren Ebenen:

  • Es gibt kein Mischen, das initialisiert werden müsste: Das BU listet die Stimmzettel in Tracker-Reihenfolge, also nach dem Hash zufälliger Geheimtexte.
  • Der Speicher des Geräts ist eine Tabelle ohne fortlaufende Kennung, indiziert nach (Gerät, Tracker): Die gespeicherte Reihenfolge ist die des Hashs, nicht die des Eingangs.
  • Kein Eintrag pro Stimme mit Uhrzeit; das SQLite-Journal im DELETE-Modus und secure_delete löschen, was übrig bleiben könnte.
  • Das Verzeichnis speichert nicht die Reihenfolge des Erscheinens, und der Vorstand signiert blind.
  • Der Schlüssel jedes abgegebenen Stimmzettels existiert nach der Abgabe nicht mehr.

In einem statistischen Test mit 160 Stimmzetteln pro Kandidat war das erste Bild bei 49 % der Stimmzettel des einen Kandidaten und 50 % des anderen „ungerade“ — wie bei von der Stimme unabhängigen Werten zu erwarten.

14. Grenzen und künftige Arbeit

Zu sagen, was nicht gelöst ist, gehört zur Sicherheit.

  • Wahlgeheimnis gegenüber einem manipulierten Gerät. Das Gerät sieht die Stimme, wie das heutige. Manipuliert, kann es den Zufall so wählen, dass die Bilder den Kandidaten „kodieren“ — ein im Labor demonstrierter verdeckter Kanal (20 von 20 Stimmen offengelegt mit höchstens einigen Dutzend Verschlüsselungen pro Stimme). Die Integrität hängt nicht vom Vertrauen in das Gerät ab; das Wahlgeheimnis ihm gegenüber schon. Künftig: Zufall aus einem zweiten, unabhängigen Gerät mit Neuverschlüsselung vor dem Siegel.
  • Ein Insider mit Geräte- und Vorstandsschlüssel kann ein mathematisch perfektes Wahllokal fabrizieren. Ertappt wird er durch die Wähler und das Papier-BU; deshalb bleiben Papier und die Fotos der Beobachter unverzichtbar.
  • Clash-Angriff zwischen Wählern: Ein manipuliertes Gerät könnte zwei Wählern denselben Stimmzettel zeigen. Jeder findet für sich „seinen“ Code; entdeckt wird das nur durch den Vergleich von Belegen.
  • Der Test ist probabilistisch und hängt davon ab, wie viele Wähler testen.
  • Drei von drei Trustees. Im Produktivbetrieb: Schwelle t-aus-n mit verteilter Schlüsselerzeugung.
  • RSA-FDH bei den Nachweisen. Im Produktivbetrieb: standardisierte blinde Signaturen (RFC 9474).
  • Schlüssel in Software. Im Produktivbetrieb: Hardwaremodule (HSM/TPM), Measured Boot und reproduzierbare Builds.
  • Zwang vor Ort (jemand in der Kabine, ein Foto des Bildschirms) liegt außerhalb der Reichweite der Kryptografie.
  • Code nicht von Dritten geprüft.

15. Einführung ohne Drucker: Beleg per QR-Code

Ein Thermodrucker in jedem Gerät (dazu Papier, Wartung und Logistik) ist der teuerste Posten dieses Entwurfs. Um ohne diese Kosten zu beginnen, kann der Beleg digital ausgegeben werden, am Wahlhelfer-Terminal, nach der Stimmabgabe:

  1. Der Wähler wählt (und testet, wenn er möchte) am Gerät wie oben beschrieben. Das Gerät zeigt wie immer Bilder, Code und Prüfcode auf dem eigenen Bildschirm.
  2. Wenn der Wähler bestätigt, sendet das Gerät den Beleg über denselben lokalen Kanal, den es schon für die Freigabe nutzt, ohne Internet an das Wahlhelfer-Terminal.
  3. Der Wähler verlässt die Kabine, und das Terminal zeigt einen QR-Code mit dem Beleg in einem ihm zugewandten Bereich des Bildschirms. Er fotografiert den Code mit dem Handy, und der Bildschirm wird geleert, sobald der nächste Wähler freigegeben wird.
  4. Zu Hause liest die Prüfseite oder der Offline-Validator den QR-Code und führt dieselben Prüfungen wie beim Papier durch: Stimme, Test und BU.

Was im QR-Code steht

Genau das, was auf dem Papier steht: Stimmcode, Prüfcode, Namen der Bilder und die Signatur des Geräts über den Beleg. Für jeden Test der erklärte Kandidat, der Code, der Schlüssel des Teststimmzettels und die signierte Erklärung. Mit ein oder zwei Teststimmzetteln sind das einige hundert Zeichen, die in einen mittelgroßen QR-Code passen, der sich leicht vom Bildschirm lesen lässt. Ist der Code eine Adresse der Prüfseite, müssen die Daten hinter das # (das URL-Fragment), das der Browser nicht an den Server sendet: 

https://<Prüfseite>/verificar#v=1&c=0100123WGFTT&k=9RD2RJJP&s=…&t=…

Warum am Wahlhelfer-Terminal und nicht in der Kabine

  • Das Gesetz verbietet Handys in der Kabine. Das brasilianische Gesetz 9.504/1997, Art. 91-A, einziger Absatz, verbietet das Mitführen von Handys und Fotokameras in die Wahlkabine. Mit dem QR-Code am Terminal benutzt der Wähler das Handy erst nach dem Verlassen.
  • Das Terminal existiert bereits. Keine neue Hardware, nur Software. Die Einführungskosten liegen nahe null.
  • Papier bleibt möglich. Beide Formen können nebeneinander bestehen: QR-Code als Standard und Papier für alle, die es verlangen oder kein Handy haben. Das erlaubt einen schrittweisen Übergang, Lokal für Lokal.

Was sich für die Sicherheit ändert

PunktAnalyse

16. Nachvollziehen

Der Prototyp läuft auf einem einzigen Computer, ohne Internetzugang während der Ausführung. Code: github.com/tauz-hub/TAI-VOTE.

git clone https://github.com/tauz-hub/TAI-VOTE.git
cd TAI-VOTE
npm install
npm run dev               # http://127.0.0.1:3000
npm run teste             # Protokoll im Speicher: Prüfer, zu Hause wiederholter Test und 14 Angriffe
npm run teste:invasao     # vollständige Wahl über die echten Module + Penetrationsbericht
npm run validador         # erzeugt den Offline-Validator (eine einzelne HTML-Datei)
npm run auditar -- pacote.json
npm run verificar -- pacote.json <Code> ["Testschlüssel"]
npm run verificar -- pacote.json --bu 010-0123

Ablauf der Demo

  1. Admin → Wahl: Legen Sie die Wahl an (Kandidaten lassen sich bearbeiten).
  2. Trustees: Erzeugen Sie die drei Schlüssel; danach in Admin Wahl eröffnen.
  3. Register: Erzeugen Sie fiktive Wähler.
  4. Wahlhelfer: Öffnen Sie Terminal und Gerät in getrennten Fenstern. Am Gerät über die Tastatur installieren (Zone und Lokal) und CONFIRMA zum Laden drücken. Am Terminal das Wahllokal öffnen.
  5. Wählen: Einen Wähler freigeben, eine Nummer eingeben, TESTAR und dann CONFIRMA drücken; den Beleg aufbewahren.
  6. Schließen: Das Lokal schließen (BU) und das Medium übertragen; in Admin die Annahme beenden; in Trustees entschlüsseln.
  7. Zu Hause: Stimme prüfen (Code), Test prüfen (Beleg einfügen), Protokoll des Wahllokals und Prüfung.
  8. Betrug: Admin → Angriffslabor → Die 7 Beispielgeräte anlegen → Alles simulieren und übertragen → Zu Hause prüfen.

Um nicht von der heruntergeladenen Validator-Datei abzuhängen, erzeugen Sie sie aus dem Quellcode neu und vergleichen den SHA-256: Der Build ist deterministisch. Die vollständige Spezifikation — Formate, Hash-Domänen, Prüfungen und API — liegt dem Code bei, und eine unabhängige Implementierung (zum Beispiel in Python) muss die Pakete des Prototyps akzeptieren und dieselben Manipulationen ablehnen.
