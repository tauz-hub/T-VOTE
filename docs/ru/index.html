T-VOTE: электронная урна, которую избиратель проверяет дома

Как голосовать на урне, которая работает как нынешняя бразильская — участок без интернета, член избирательной комиссии, нулевой протокол утром, итоговый протокол на двери школы, — а потом на своём компьютере проверить, что ваш голос был записан и учтён так, как вы проголосовали, не доверяя ни урне, ни серверу, ни организаторам выборов.

Академический прототип с открытым кодом Протокол v4 · участок без сети Эталонная реализация: TypeScript (Next.js + SQLite)

Открытый код: скачайте, запустите и проверьте

Вся описанная здесь система опубликована. Любой может прочитать код, запустить демонстрационные выборы на своём компьютере и повторить проверки.

Интерфейс, код и спецификация прототипа — на португальском языке; снимки экрана в части II приведены как есть.

Это исследовательский прототип, а не сертифицированная система. Он предназначен для изучения и демонстрации проверяемой схемы голосования. Он не проходил независимого аудита и не должен использоваться на реальных выборах. Кандидаты в примерах этого документа вымышлены; прототип может загружать публичные агитационные фотографии только для реалистичности демонстрации, и ни один пример не отдаёт предпочтения какому-либо кандидату (в тестах на фальсификацию выигрывающий кандидат выбирается жребием).

Краткое изложение

T-VOTE — это схема электронного голосования со сквозной проверяемостью (англ. end-to-end verifiable, E2E-V). Она сохраняет привычный бразильскому избирателю порядок и добавляет три проверки, которые любой может выполнить дома с помощью программы с открытым кодом и публичной копии выборов:

  • Мой голос: код, напечатанный на квитанции, ведёт к вашему зашифрованному голосу в публичном списке вашего участка, с теми же двумя картинками, которые показала урна. Это доказывает, что голос был записан и вошёл в подсчёт, — не раскрывая, за кого вы голосовали.
  • Моя проверка: если вы нажали на урне TESTAR («проверить»), на квитанции есть ключ этого проверочного бюллетеня. Дома компьютер повторяет вычисление и показывает, какой кандидат был внутри. Если урна солгала, подписанная ею бумага служит доказательством.
  • Протокол моего участка: у итогового протокола на двери школы есть код; опубликованный протокол должен иметь тот же код и те же числа, а числа должны совпадать с криптографическим подсчётом.

В основе лежат проверенные криптографические примитивы: гомоморфное шифрование Эль-Гамаля над группой ristretto255, доказательства с нулевым разглашением, слепые подписи для анонимных удостоверений, подписи Ed25519 и подписанная цепочка блоков. Подсчёт выполняют три хранителя ключа (trustees), которые могут расшифровать только сумму голосов каждого участка, но никогда отдельный голос. Документ сначала объясняет систему простым языком, затем показывает каждый экран прототипа и потом переходит к техническим деталям; в конце — проведённые против системы тесты на проникновение и все источники.

Часть I

Для всех

Без математики: что вы делаете у урны, что уносите домой и что можете проверить.

1. Идея в нескольких словах

Сегодня, голосуя, вы вынуждены доверять тому, что урна записала набранный вами номер и что итог вашего участка был подсчитан правильно. У нынешней урны много механизмов контроля, чтобы заслужить это доверие, но сам избиратель не может проверить свой голос.

В T-VOTE урна по-прежнему стоит в углу зала, без интернета, и вы нажимаете те же кнопки. Разница в том, что она берёт на себя обязательство относительно записанного ещё до того, как узнает, что вы будете делать, а затем оставляет следы, которые вы проверяете дома. Если она жульничает, это обнаруживается. Если жульничает орган, суммирующий голоса, это тоже обнаруживается. И при этом никто — даже вы — не может доказать другому человеку, за кого вы проголосовали. Именно это предотвращает покупку голосов.

2. В день выборов

Всё происходит на участке, как сегодня. Урна и терминал члена комиссии общаются только друг с другом; ни одно из устройств не подключено к интернету.

  1. Член комиссии проверяет документ и разблокирует урну

    Как сегодня. Урна получает только «можно голосовать» — вашего имени она никогда не узнаёт.

  2. Вы набираете номер и видите фотографию

    На экране — имя, партия и фотография кандидата. Урна сама сверяет фотографию с отпечатком, опубликованным до выборов, чтобы её никто не смог подменить.

  3. Вы нажимаете CONFIRMA, и появляются две картинки и код

    Например: 🍄 ГРИБ и 🦴 КОСТЬ, а также код 010 0123 J7K6T. Над каждым словом есть рисунок — для тех, кто не умеет читать. Запомните картинки; код будет напечатан.

  4. Теперь вы выбираете клавишу

    CONFIRMA («подтвердить») записывает голос. TESTAR («проверить») открывает этот бюллетень, чтобы вы увидели, что записала урна (он аннулируется, и вы голосуете заново, не набирая номер повторно). CORRIGE («исправить») возвращает к выбору.

  5. Выходит одна-единственная бумажка

    На квитанции — код голоса, 8-символьный «контрольный код» и названия двух картинок. Если вы проверяли урну, на той же бумаге есть и проверка: кандидат, которого урна якобы нашла, код проверки и ключ этого проверочного бюллетеня.

    На первом этапе, без принтеров, квитанцию можно выдавать в виде QR-кода на экране терминала члена комиссии: избиратель выходит из кабины и фотографирует код телефоном (раздел 15).

Если она часто записывает не того кандидата, которого показывает, каждый проверяющий избиратель — это шанс её поймать. Можно проверять даже номер кандидата, за которого вы голосовать не собираетесь.

В конце дня

Член комиссии закрывает участок, и урна, как и сегодня, печатает итоговый протокол (BU, boletim de urna) с голосами за каждого кандидата. Один экземпляр вывешивается на двери школы. Новое — код BU (например 0d94 dbf4 9855 15b1), который однозначно определяет именно этот протокол. Затем файл участка («носитель») доставляется в избирательный орган, который всё проверяет и публикует в цепочке блоков, доступной для скачивания всем.

3. Дома: три проверки

После публикации участка вы можете проверить его на сайте выборов, с помощью одного файла, работающего без интернета, или программы командной строки. Все три используют один и тот же открытый код и выполняют все вычисления на вашем компьютере.

Мой голос

Введите код с квитанции. Должны появиться те же 2 картинки, что вы видели на урне, и тот же контрольный код, что на бумаге.

Доказывает: ваш голос есть в публичном списке вашего участка, он действителен и учтён.

Моя проверка

Вставьте раздел «ПРОВЕРКА УРНЫ» с квитанции. Компьютер заново шифрует каждого кандидата ключом с бумаги и находит того, кто был внутри.

Доказывает: урна сказала правду — или солгала, и её подпись на бумаге это показывает.

BU участка

Введите зону и участок. Код BU и опубликованные числа должны совпадать с бумагой на двери школы.

Доказывает: никто не подменил ваш участок после того, как данные покинули школу.

Реальный пример — проверка двух тестов, проведённых на пробном запуске системы: первый тест, где урна заявила номер 80, был повторён дома и дал 80; второй, заявленный как 27, дал 27; оба заявления имели действительную подпись урны. Результат: «урна участка 001-0001 прошла ваши 2 проверки».

4. Почему по бумаге никто не узнает ваш голос

  • Код и картинки не зависят от голоса. Они получаются из подписи урны над шифротекстом, который у каждого бюллетеня свой. Два избирателя, проголосовавшие за одного кандидата, получают никак не связанные коды. Можно публично сказать «мои картинки — 🌻 ПОДСОЛНУХ и ☄️ КОМЕТА», ничего не раскрыв.
  • Поданный голос никогда не открывается. У каждого бюллетеня свой ключ; ключ поданного голоса уничтожается в урне в тот же момент. Публично существует только шифротекст.
  • Открывается только сумма. Три хранителя ключа, у каждого из которых есть часть, вместе расшифровывают лишь итог каждого участка. Ни один из них в одиночку ничего открыть не может.
  • Проверка — это не голос. Проверочный бюллетень аннулируется. Показ проверки не доказывает голос, потому что можно проверить одного кандидата, а проголосовать за другого.
  • Ни времени, ни порядка. Ничто не хранит порядок поступления голосов и время каждого из них. Именно это позволило на открытом тестировании 2012 года восстановить порядок голосов в тогдашней бразильской урне.
  • Против голосования под давлением. Поскольку даже сам избиратель не может доказать, за кого проголосовал, тому, кто покупает голоса или принуждает, нечего требовать. См. раздел 13.2.

6. Частые вопросы

Некоторые из этих вопросов прозвучали в публичном обсуждении белой книги. Это обоснованные сомнения: на каждый здесь есть краткий ответ, а в части III — технический раздел.

Разве урна не может просто показать «проверка пройдена», солгав?

Может, и поэтому значение имеет только проверка вне урны. Поддельная урна способна лгать на своём экране, но не может заставить вычисления вашего компьютера дать другой результат: она взяла обязательство по бюллетеню, не зная, будете ли вы проверять, а напечатанный ею ключ открывает только этот бюллетень.

Нужно ли разбираться в криптографии, чтобы проверить?

Нет. Вы вводите код, смотрите, совпадают ли картинки, и, если проверяли урну, вставляете текст проверки. Ответ будет «ваш голос на месте», «урна была честной» или «фальсификация».

Могут ли меня заставить показать квитанцию, чтобы доказать голос?

Попросить могут, но квитанция ничего не доказывает: код не указывает на кандидата, а проверка относится к аннулированному бюллетеню. Покупатель голосов не получает никаких гарантий.

А если я потеряю квитанцию?

Ваш голос по-прежнему учитывается. Вы теряете лишь возможность его проверить. Итог участка остаётся доступным для аудита кем угодно.

Это блокчейн? Как он работает, если у урны нет интернета?

Используется часть технологии блокчейна: структура блоков, связанных хешами и подписанных цифровой подписью, которую любой может скачать и пересчитать. Другая часть не используется: нет ни майнинга, ни криптовалюты, ни сети компьютеров, соревнующихся за право записи, — пишет только избирательный орган. Урна весь день работает без сети, как сегодня; в конце она создаёт подписанный файл, который доставляется в избирательный орган, и только тогда он публикуется в цепочке. Урна никогда не обращается к цепочке. Подробнее в разделе 7.4.

Сегодня урна перемешивает голоса, чтобы никто не знал порядок. Как найти свой голос, не нарушив этого?

Вы находите не голос в открытом виде, а свой зашифрованный бюллетень. Каждый бюллетень шифруется со свежей случайностью и хранится в порядке хеша шифротекста, без времени. Код на квитанции указывает на шифротекст, а проверка доказывает, что он включён и учтён в сумме, — не открывая его. Перемешивать нечего, потому что голоса в открытом виде не хранятся. Подробнее в разделе 13.1.

А как же голосование под давлением? Если я могу проверить свой голос, разве меня не могут заставить доказать, за кого я проголосовал?

Это самое важное требование, и схема исходит из него. Квитанция не доказывает голос: код не зависит от кандидата, и даже вы не можете открыть поданный бюллетень, потому что его ключ уничтожен в урне. Открыть можно только бюллетень TESTAR, а он аннулируется — можно проверить кандидата, которого требует принуждающий, и проголосовать за другого. Покупатель голосов или принуждающий не получает никаких гарантий. Оставшиеся ограничения — в разделе 13.2.

Как это выдержит 160 миллионов избирателей, не потребляя энергию целой страны?

Энергопотребление блокчейнов связано с майнингом, которого здесь нет: пишет только избирательный орган, и каждый блок подписан. По измерениям в прототипе бюллетень занимает около 12 КБ, а его аудит занимает около 0,1 секунды на одном обычном ядре процессора. Избиратель проверяет только свой участок; полный аудит всей страны укладывается в несколько сотен ядер примерно за сутки с потреблением порядка десятков кВт·ч. Цифры и ограничения — в разделе 7.5.

А если на участке нет принтера?

Квитанцию можно выдать в виде QR-кода на экране терминала члена комиссии после голосования. Избиратель, уже выйдя из кабины, фотографирует код телефоном. Содержимое то же, что на бумаге, и подписано урной, поэтому терминал не может его незаметно изменить. У кого нет телефона, может попросить печатную версию.

Замедляет ли проверка урны очередь?

На несколько секунд. Проверочный бюллетень открывается сразу, а чтобы проголосовать по-настоящему, достаточно снова нажать CONFIRMA — без повторного набора номера.

7.4 Чем является цепочка блоков — и чем не является

Обоснованный вопрос: как встроить блокчейн в урну без интернета? Ответ: во время голосования урна цепочку не использует. Она работает без сети и в конце дня передаёт подписанный файл (носитель, раздел 7.1). Только после этого избирательный орган публикует этот файл в цепочке.

T-VOTE использует часть технологии блокчейна — структуру данных. Записи хранятся в блоках, каждый блок содержит хеш предыдущего и подписан, ничего нельзя изменить или удалить, не нарушив связей и подписей, и любой может скачать цепочку и всё пересчитать. Другая часть — децентрализованный консенсус — не используется:

СвойствоБлокчейн криптовалютыЦепочка T-VOTE
Блоки, связанные хешамиДаДа

Технически это пополняемая публичная доска объявлений (public bulletin board) — та же идея, что и журналы Certificate Transparency для HTTPS-сертификатов. Безопасность обеспечивается не согласием множества компьютеров, а подписями (избирательный орган не может изменить участок без ключа урны) и публичной проверкой. Если бы избирательный орган показывал разным людям разные цепочки, это обнаружилось бы при сравнении хеша последнего блока между аудиторами и с бумажными BU; в реальной системе этот итоговый хеш следовало бы публиковать в нескольких независимых местах.

Криптография голоса — Эль-Гамаль, доказательства с нулевым разглашением, слепые подписи (раздел 8) — пришла не из блокчейна, а из литературы о проверяемом голосовании. Хеши и цифровые подписи общие для обеих областей.

7.5 Масштаб: 160 миллионов избирателей

Ещё один обоснованный вопрос: как выдержать 160 миллионов записей, не расходуя энергию целой страны? Энергопотребление блокчейнов криптовалют связано с майнингом, которого здесь нет. Реальные затраты — хранение и проверка бюллетеней. Измерено в прототипе (scripts/medir-escala.ts) на участке из 300 избирателей с 14 вариантами (12 кандидатов, пустой и недействительный), на обычном настольном компьютере, с неоптимизированной реализацией на JavaScript:

ПоказательЗначение
Один бюллетень (шифротексты, доказательства, удостоверение, подпись и печать, в JSON)≈ 11,7 КБ
Блок участка из 300 избирателей≈ 3,5 МБ
Полный аудит одного бюллетеня≈ 0,1 с на ядро
Полный аудит участка из 300 избирателей≈ 31 с на ядро

Прогноз для 160 миллионов бюллетеней, одна должность с 14 вариантами:

  • Хранение: около 1,9 ТБ — помещается на обычный диск. Компактный двоичный формат уменьшил бы объём.
  • Полный аудит страны: около 4 600 ядро-часов; на 200 ядрах — примерно сутки. При 10 Вт на ядро это около 47 кВт·ч — примерно месячное потребление холодильника.
  • Проверка избирателем: он скачивает только свой участок (несколько МБ) и проверяет его за секунды.

Реальное ограничение: должности с большим числом кандидатов. Прототип шифрует по одной позиции на вариант. Это хорошо работает для должностей с небольшим числом кандидатов, таких как президент или губернатор, но не для депутатов, которых в одном штате могут быть сотни: бюллетень занял бы сотни КБ на одну должность. Кроме того, на всеобщих выборах в одном голосовании несколько должностей, и каждая добавляет объём и время. Для этого понадобилась бы другая техника, например проверяемое перемешивание (mix-net), применяемое в других системах проверяемого голосования, вместо гомоморфной суммы по вариантам.

8.2 Бюллетень

При k вариантах (кандидаты, пустой и недействительный) бюллетень шифрует вектор с 1 в выбранном варианте и 0 в остальных. Для каждого варианта i:

a_i = g^(r_i) b_i = g^(m_i) · h^(r_i) m_i ∈ {0, 1}, Σ m_i = 1

h — общий открытый ключ трёх хранителей. Каждая пара (ai, bi) сопровождается доказательством, что она шифрует 0 или 1, а бюллетень — доказательством, что сумма шифрует ровно 1, без раскрытия выбранного варианта. Трекер бюллетеня — SHA-256 всех шифротекстов.

Ключ бюллетеня

У каждого бюллетеня есть 128-битное зерно из CSPRNG урны, и вся случайность выводится из него:

r_i = H("T-VOTE/aleatoriedade/v1", [зерно, хеш_выборов, i]) mod L

У поданного бюллетеня зерно уничтожается в момент подачи. У проверочного оно раскрывается, публикуется в BU и печатается на квитанции: с ним любой компьютер повторяет шифротексты каждого возможного варианта и выясняет, какой из них был зашифрован.

8.3 Анонимное удостоверение

После допуска членом комиссии урна генерирует эфемерную пару Ed25519 и запрашивает у терминала комиссии слепую подпись открытого ключа. Комиссия подписывает, не видя, что подписывает, и лишь увеличивает свой счётчик на 1; он печатается в BU как явка. Бюллетень подписывается этим удостоверением, а нуллификатор (SHA-256 ключа удостоверения) не позволяет одному удостоверению проголосовать дважды. Ни комиссия, ни список не могут связать удостоверение с избирателем.

8.4 Печать, код, картинки и контрольный код

Как только бюллетень запечатан, урна скрепляет его своим ключом. Печать детерминирована (Ed25519):

печать = Ed25519(ключ_урны, SHA-256("T-VOTE/selo/v1|" ‖ {выборы, трекер, участок})) v = SHA-256("T-VOTE/verificacao/v1|" ‖ печать) картинки = КАРТИНКИ[v[0]], КАРТИНКИ[v[1]] 16 бит (256 картинок) код = зона ‖ участок ‖ base32(25 бит из v[2..6]) 25 случайных бит контроль = base32(40 бит из v[6..11]) 40 бит

Код использует base32 Крокфорда (без I, L, O и U); при чтении O превращается в 0, а I/L — в 1. Он уникален в пределах участка, а участок в префиксе делает его уникальным в пределах выборов. 256 картинок подобраны так, чтобы их можно было нарисовать, без пар, отличающихся одной буквой, и без политического, религиозного или оружейного содержания.

Зачем нужен контрольный код. У 2 картинок всего 16 бит: в эксперименте поддельная урна менее чем за тысячу шифрований нашла два бюллетеня (по одному на кандидата) с одинаковыми картинками — и могла бы открыть один при проверке, а подать другой. С кодом и картинками (41 бит) такая пара потребовала бы около 220 шифрований — всё ещё доступно подготовленной урне. Контрольный код, напечатанный до решения, повышает обязательство до 81 бита: та же атака требует около 240 шифрований на месте, что неосуществимо.

8.5 Проверка урны (вызов Беналоха)

Увидев обязательство, избиратель может нажать TESTAR. Урна раскрывает зерно, сохраняет открытый бюллетень для BU и подписывает заявление с кандидатом, которого якобы нашла, и напечатанным ключом:

заявление = Ed25519(ключ_урны, SHA-256("T-VOTE/declaracao-teste/v2|" ‖ {выборы, участок, трекер, вариант, зерно}))

Дома валидатор заново шифрует каждый вариант зерном с бумаги и ищет единственный, который точно воспроизводит шифротексты, запечатанные под этим кодом. Если это не заявленный вариант, урна солгала, и подпись превращает это в передаваемое доказательство. Если кто-то изменит бумагу, подпись перестанет совпадать — поддельная бумага не может обвинить честную урну.

8.6 Нулевой протокол и итоговый протокол

Оба — канонические JSON-документы, подписанные урной:

  • Нулевой протокол: выборы, участок, ключ урны, ключ комиссии, хеш ПО, число бюллетеней в памяти (ноль) и время открытия.
  • BU: ссылается на хеш нулевого протокола и содержит явку (счётчик комиссии), все бюллетени и проверочные бюллетени в порядке трекеров, открытый подсчёт по вариантам (то, что печатается) и гомоморфный агрегат шифротекстов.

Код BU, печатаемый на бумаге, — это первые 16 шестнадцатеричных символов хеша документа.

8.7 Подсчёт по участкам

Ключ выборов — произведение ключей трёх хранителей. Для каждого участка s и варианта j с агрегатом (Asj, Bsj):

D_sj,t = A_sj^(x_t) (с доказательством Чаума — Педерсена; контекст включает участок) g^(m_sj) = B_sj / (D_sj,1 · D_sj,2 · D_sj,3) → m_sj перебором в [0, число бюллетеней]

Перед расшифровкой каждый хранитель проверяет пакет и пересчитывает агрегат; он отказывается расшифровывать что-либо, кроме суммы, которую пересчитал сам. Расшифровка по участкам позволяет сравнить каждый напечатанный BU с криптографическим подсчётом.

11. Всеобщий аудит

Аудитор получает только публичный пакет (цепочку блоков) и повторяет 22 проверки:

  1. Целостность цепочки (хеш и связь каждого блока)
  2. Подпись доски на каждом блоке
  3. Манифест выборов (генезис) и версия протокола
  4. Порядок фаз
  5. Ключи хранителей с доказательством Шнорра
  6. Национальный нулевой протокол и общий ключ
  7. Загрузка урн: собственный ключ, без повторов, ПО совпадает с генезисом, нет загрузки после носителя
  8. Носители подписаны загруженной урной, нулевой протокол с нулями, один носитель на участок
  9. Бюллетени без порядка поступления и без времени (точные поля, порядок трекеров)
  10. Действительные анонимные удостоверения комиссии участка
  11. Подпись каждого бюллетеня
  12. Доказательства с нулевым разглашением
  13. Пересчитанные трекеры и нуллификаторы
  14. Код, картинки и контрольный код выведены из печати; коды уникальны
  15. Одно удостоверение — один голос
  16. Проверочные бюллетени совпадают с раскрытым зерном
  17. Бюллетени ≤ явка; подсчёт BU даёт число бюллетеней
  18. Гомоморфная сумма по участку
  19. Закрытие перечисляет ровно полученные участки и участки без носителя
  20. Частичная расшифровка каждого хранителя, по участкам, с доказательством
  21. Напечатанный BU = криптографический подсчёт
  22. Опубликованный результат = пересчитанный, по участкам и в целом

13. Тайна голосования, принуждение и урок TPS 2012

На открытом тестировании безопасности (TPS) бразильской урны в 2012 году исследователи показали, что порядок голосов, записанных тогдашней урной, можно восстановить, поскольку перемешивание использовало некриптографический генератор, инициализированный временем. T-VOTE отвечает на это на нескольких уровнях:

  • Нет перемешивания, которое нужно инициализировать: BU перечисляет бюллетени в порядке трекеров, то есть хешей случайных шифротекстов.
  • Память урны — таблица без последовательного идентификатора, индексированная по (урна, трекер): хранится порядок хешей, а не порядок поступления.
  • Никаких записей по каждому голосу со временем; журнал SQLite в режиме DELETE и secure_delete стирают возможные остатки.
  • Список не хранит порядок прихода, а комиссия подписывает вслепую.
  • Ключ каждого поданного бюллетеня перестаёт существовать после подачи.

В статистическом тесте со 160 бюллетенями на кандидата первая картинка оказалась «нечётной» в 49% бюллетеней одного кандидата и в 50% — другого, как и ожидается для значений, не зависящих от голоса.

13.1 Перемешивать или шифровать

Обоснованный вопрос: если урна перемешивает голоса именно для того, чтобы их нельзя было отследить, как потом связать мой голос с урной? Нынешняя урна хранит голоса в открытом виде в цифровом реестре голосов (RDV) и перемешивает их, чтобы порядок записи не выдавал порядок очереди. TPS 2012 показал риск: если перемешивание предсказуемо, порядок можно восстановить и, сопоставив с порядком прихода избирателей, раскрыть голоса.

T-VOTE не хранит голосов в открытом виде, поэтому не зависит от перемешивания:

  • Каждый бюллетень шифруется со свежей случайностью; два бюллетеня за одного кандидата неразличимы.
  • Порядок хранения — порядок трекеров (хешей шифротекстов): случайный и не связанный с приходом.
  • Избиратель находит свой шифротекст по коду на квитанции. Это доказывает, что он включён и учтён, но не то, что в нём.
  • Расшифровывается только сумма каждого участка (раздел 8.7).

Стоит отметить следствие: на участке, где все проголосовали за одного кандидата, результат раскрывает голоса всех, — но так происходит и сегодня, потому что BU каждого участка публичен.

13.2 Принуждение и покупка голосов

Это самая важная критика любой проверяемой системы, и она справедлива: в регионах с насилием, если голос можно доказать, избирателей могут заставить его доказывать. Требуемое свойство называется отсутствием квитанции (receipt-freeness): избиратель не может доказать свой голос никому, даже если захочет.

  • Поддельная урна, раскрывающая голос через картинки (скрытый канал, раздел 14): избиратель этого не контролирует; защита — предмет дальнейшей работы.

Итог: T-VOTE не облегчает покупку голосов и принуждение по сравнению с сегодняшним днём — то, что избиратель уносит домой, ни для кого не является доказательством. Если кто-то найдёт способ, которым избиратель может доказать свой голос с помощью того, что уносит домой, это серьёзная уязвимость, и о ней нужно сообщить.

14. Ограничения и дальнейшая работа

Говорить о нерешённом — часть безопасности.

  • Тайна голосования против поддельной урны. Урна видит голос, как и нынешняя. Будучи поддельной, она может подбирать случайность так, чтобы картинки «кодировали» кандидата, — скрытый канал, продемонстрированный в лаборатории (утечка 20 из 20 голосов максимум за несколько десятков шифрований на голос). Целостность не зависит от доверия к урне; тайна голосования от неё — зависит. Дальнейшая работа: случайность от второго независимого устройства с перешифрованием до наложения печати.
  • Инсайдер с ключами урны и комиссии может сфабриковать математически безупречный участок. Его ловят избиратели и бумажный BU; поэтому бумага и фотографии наблюдателей остаются необходимыми.
  • Атака столкновения между избирателями (clash): поддельная урна может показать двум избирателям один и тот же бюллетень. Каждый по отдельности находит «свой» код; выявить это можно только сравнением квитанций.
  • Проверка вероятностная и зависит от того, сколько избирателей проверяют.
  • Три из трёх хранителей. В рабочей системе: порог t из n с распределённой генерацией ключей.
  • RSA-FDH в удостоверениях. В рабочей системе: стандартизированные слепые подписи (RFC 9474).
  • Ключи в программной среде. В рабочей системе: аппаратные модули (HSM/TPM), измеряемая загрузка и воспроизводимые сборки.
  • Принуждение на месте (кто-то в кабине, фото экрана) находится вне возможностей криптографии.
  • Код не прошёл независимый аудит.
  • Должности с большим числом кандидатов (депутаты): бюллетень с одним шифротекстом на вариант становится большим; понадобилось бы проверяемое перемешивание (mix-net). См. раздел 7.5.

15. Внедрение без принтеров: квитанция в виде QR-кода

Термопринтер в каждой урне (а также бумага, обслуживание и логистика) — самая дорогая часть этой схемы. Чтобы начать без этих затрат, квитанцию можно выдавать в цифровом виде на терминале члена комиссии, после голосования:

  1. Избиратель голосует (и, если хочет, проверяет урну), как описано выше. Урна, как всегда, показывает картинки, код и контрольный код на своём экране.
  2. Когда избиратель подтверждает выбор, урна отправляет квитанцию на терминал члена комиссии по тому же локальному каналу, который уже используется для допуска, без интернета.
  3. Избиратель выходит из кабины, и терминал показывает QR-код с квитанцией в обращённой к нему части экрана. Он фотографирует код телефоном, а экран очищается, как только допускается следующий избиратель.
  4. Дома страница проверки или офлайн-валидатор считывает QR-код и выполняет те же проверки, что и для бумаги: голос, проверка и BU.

Что содержит QR-код

Ровно то, что напечатано на бумаге: код голоса, контрольный код, названия картинок и подпись урны под квитанцией. Для каждой проверки — заявленный кандидат, код, ключ проверочного бюллетеня и подписанное заявление. При одном-двух проверочных бюллетенях это несколько сотен символов — они помещаются в QR-код среднего размера, легко считываемый с экрана. Если код является адресом страницы проверки, данные должны идти после # (фрагмента URL), который браузер не отправляет на сервер: 

https://<страница проверки>/verificar#v=1&c=0100123WGFTT&k=9RD2RJJP&s=…&t=…

Почему на терминале члена комиссии, а не в кабине

  • Закон запрещает телефоны в кабине. Бразильский закон 9.504/1997, ст. 91-A, единственный абзац, запрещает проносить в кабину для голосования мобильные телефоны и фотоаппараты. С QR-кодом на терминале избиратель пользуется телефоном только после выхода.
  • Терминал уже существует. Нового оборудования нет, только ПО. Стоимость внедрения близка к нулю.
  • Бумага остаётся возможной. Оба варианта могут сосуществовать: QR-код по умолчанию и бумага для тех, кто попросит или не имеет телефона. Это позволяет переходить постепенно, участок за участком.

В прототипе этого пока нет. Сейчас прототип печатает квитанцию на бумаге (имитация на экране). QR-код на терминале члена комиссии — предложение для первого этапа внедрения. Криптография не меняется: меняется лишь способ выдачи квитанции.

16. Как воспроизвести

Прототип работает на одном компьютере без доступа к интернету во время работы. Код: github.com/tauz-hub/T-VOTE.

Требование: Node.js 22 или новее. Скрипты запуска INICIAR.bat и iniciar.sh сами скачивают Node.js, если его нет (см. Код и загрузка).

git clone https://github.com/tauz-hub/T-VOTE.git
cd T-VOTE
npm install
npm run dev               # http://127.0.0.1:3000
npm run teste             # протокол в памяти: аудитор, проверка, повторённая дома, и 14 атак
npm run teste:invasao     # полные выборы на реальных модулях + отчёт о проникновении
npm run validador         # собирает офлайн-валидатор (один HTML-файл)
npm run auditar -- pacote.json
npm run verificar -- pacote.json <код> ["ключ проверки"]
npm run verificar -- pacote.json --bu 010-0123

Сценарий демонстрации

  1. Admin → Выборы: создайте выборы (кандидатов можно редактировать).
  2. Trustees: сгенерируйте три ключа; затем в Admin — Открыть выборы.
  3. Регистр: создайте вымышленных избирателей.
  4. Член комиссии: откройте терминал и урну в разных окнах. На урне выполните установку с клавиатуры (зона и участок) и нажмите CONFIRMA для загрузки. На терминале откройте участок.
  5. Голосование: допустите избирателя, наберите номер, нажмите TESTAR, затем CONFIRMA; сохраните квитанцию.
  6. Закрытие: закройте участок (BU) и передайте носитель; в Admin прекратите приём; в Trustees выполните расшифровку.
  7. Дома: Проверка голоса (код), Проверка теста (вставьте квитанцию), Протокол участка и Аудит.
  8. Фальсификации: Admin → Лаборатория атак → Создать 7 учебных урн → Симулировать всё и передать → Проверить дома.

Чтобы не зависеть от скачанного файла валидатора, соберите его заново из исходного кода и сравните SHA-256: сборка детерминирована. Полная спецификация — форматы, хеш-домены, проверки и API — прилагается к коду, и независимая реализация (например, на Python) должна принимать пакеты прототипа и отвергать те же подделки.
