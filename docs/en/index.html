White paper · version 1 · October 2026

T-VOTE: a voting machine that voters can check at home

How to vote on a machine that works like Brazil's current one — an offline polling station, a poll worker, a zero report in the morning, a results report posted on the school door — and later check on your own computer that your vote was recorded and counted as you cast it, without having to trust the machine, the server or whoever runs the election.

Open-source academic prototype Protocol v4 · offline polling station Reference implementation: TypeScript (Next.js + SQLite)

Open source: download, run and check

The whole system described here is published. Anyone can read the code, run the demo election on their own computer and repeat the checks.

This is a research prototype, not a certified system. It exists to study and demonstrate a verifiable voting design. It has not been audited by third parties and must not be used in real elections. The candidates in this document's examples are fictitious; the prototype can load public campaign photos only to make the demo realistic, and no example favours any candidate (in the fraud tests, the candidate who benefits is drawn at random).

Summary

T-VOTE is an end-to-end verifiable (E2E-V) electronic voting design. It keeps the flow Brazilian voters already know and adds three checks that anyone can do at home, with an open-source program and a public copy of the election:

  • My vote: the code printed on the receipt leads to your encrypted vote in the public list of your polling station, with the same two pictures the machine showed. This proves the vote was recorded and went into the count — without revealing who you voted for.
  • My test: if you pressed TESTAR (test) on the machine, the receipt carries the key of that test ballot. At home, the computer redoes the math and shows which candidate was inside it. If the machine lied, the paper it signed is proof.
  • My polling station's report: the results report posted on the school door has a code; the published report must have the same code and the same numbers, and the numbers must match the cryptographic tally.

Underneath are well-established cryptographic primitives: homomorphic ElGamal encryption over the ristretto255 group, zero-knowledge proofs, blind signatures for anonymous credentials, Ed25519 signatures and a signed chain of blocks. The tally is done by three key guardians (trustees) who can only decrypt the sum of each polling station's votes, never an individual vote. This document first explains the system in plain language, then shows every screen of the prototype, then goes into technical detail, and ends with the penetration tests run against it and all sources.

Part I

For everyone

No math: what you do at the machine, what you take home and what you can check.

1. The idea in a few words

Today, when you vote, you have to trust that the machine recorded the number you typed and that your polling station's total was added up correctly. The current machine has many controls to earn that trust, but the voter, alone, has no way to check their own vote.

With T-VOTE, the machine still sits in the corner of the room, offline, and you still press the same buttons. The difference is that it commits to what it recorded before knowing what you will do, and then leaves traces you can check at home. If it cheats, the cheating shows. If the body that adds up the votes cheats, that shows too. And even so, nobody — not even you — can prove to someone else who you voted for. That is what prevents vote buying.

2. On election day

Everything happens at the polling station, as today. The machine and the poll worker's terminal only talk to each other; neither is connected to the internet.

  1. The poll worker checks your ID and releases the machine

    As today. The machine only receives a "may vote" — it never learns your name.

  2. You type the number and see the photo

    The screen shows the candidate's name, party and photo. The machine itself checks the photo against a fingerprint published before the election, so nobody can swap it.

  3. You press CONFIRMA and two pictures and a code appear

    For example: 🍄 MUSHROOM and 🦴 BONE, and the code 010 0123 J7K6T. Each picture has a drawing above the word for people who cannot read. Remember the pictures; the code is printed.

  4. Now you choose a key

    CONFIRMA (confirm) records the vote. TESTAR (test) opens that ballot so you can see what the machine recorded (it is cancelled and you vote again, without retyping). CORRIGE (correct) goes back to choose another.

  5. One single slip of paper comes out

    The receipt has the vote code, an 8-character "check code" and the names of the two pictures. If you tested, the same paper carries the test: the candidate the machine says it found, the test code and the key of that test ballot.

    In a first phase, without printers, the receipt can be delivered as a QR code on the poll worker's terminal screen: the voter leaves the booth and photographs the code with their phone (section 15).

Why test? When you press TESTAR, the machine has already shown that ballot's code and pictures — it committed before knowing whether you would vote or test. If it tends to record a different candidate from the one it shows, every voter who tests is a chance of catching it. You can even test by typing the number of someone you will not vote for.

At the end of the day

The poll worker closes the polling station and the machine prints the results report (BU, boletim de urna), as today, with each candidate's votes. One copy goes on the school door. What's new is the BU code (for example 0d94 dbf4 9855 15b1), which identifies exactly that report. Then the polling station's file (the "media") is taken to the election authority, which checks everything and publishes it on a chain of blocks that anyone can download.

3. At home: the three checks

Once the polling station is published, you can check using the election website, a single file that works offline, or a command-line program. All three use the same open source code and do all the math on your computer.

My vote

Type the receipt code. The same 2 pictures you saw on the machine and the same check code as on the paper must appear.

Proves: your vote is in your polling station's public list, is valid and was added up.

My test

Paste the "MACHINE TEST" part of the receipt. The computer re-encrypts every candidate with the key on the paper and finds which one was inside.

Proves: the machine told the truth — or lied, and its signature on the paper shows it.

The polling station's BU

Type zone and station. The BU code and the published numbers must equal those on the paper on the school door.

Proves: nobody swapped your polling station after it left the school.

A real example, from checking two tests made in a trial run of the system: the first test, in which the machine declared number 80, was redone at home and gave 80; the second, declared 27, gave 27; both declarations had a valid machine signature. Result: "the machine at polling station 001-0001 passed your 2 tests".

4. Why nobody can learn your vote from the paper

  • The code and the pictures do not come from the vote. They come from the machine's signature over an encryption that is different for every ballot. Two voters who vote for the same candidate get codes with no relation to each other. You can say in public "my pictures were 🌻 SUNFLOWER and ☄️ COMET" without revealing anything.
  • The cast vote is never opened. Each ballot has its own key; the key of a cast vote is destroyed in the machine at that very moment. All that exists publicly is the ciphertext.
  • Only the sum is opened. Three key guardians, each holding a piece, jointly decrypt only each polling station's total. None of them, alone, can open anything.
  • The test is not the vote. The test ballot is cancelled. Showing the test does not prove the vote, because you can test one candidate and vote for another.
  • No time and no order. Nothing keeps the order in which votes arrived or the time of each one. That is exactly what allowed researchers, in a 2012 public test, to reconstruct the order of votes on the Brazilian machine of that time.
  • Against coerced voting. Since not even the voter can prove who they voted for, anyone trying to buy or coerce votes has nothing to demand. See section 13.2.

5. What happens if someone cheats

The system was attacked on purpose, in many ways. This table shows who notices each kind of cheating:

CheatingWho notices
The machine records a different candidate from the one it shows and lies in the testThe voter who tested, at home, with the key on the paper
The machine shows your code but records another ballotThe voter, in "My vote": their code does not exist in the polling station
The machine prints a fake key or makes the test ballot disappearThe voter who tested: the key does not open the ballot, or the test is not published
Someone alters votes in the databaseAny auditor: the signatures stop matching
The election authority removes a vote or changes the resultAny auditor: the machine's signature or the tally proofs stop matching
An insider, with keys extracted from the machine itself, rebuilds a whole polling stationThat station's voters (their codes disappear) and the BU posted on the school door
Someone makes a whole polling station disappearThe paper BU and the station's voters

The lesson: math, paper and voter complement each other. None of the three catches everything alone — together, they cover the frauds tested.

6. Frequently asked questions

Some of these questions came from the public discussion of this white paper. They are legitimate concerns: each has a short answer here and a technical section in Part III.

Couldn't the machine simply show "verification OK" while lying?

It could, and that is why the verification that counts is the one done outside the machine. A rigged machine can lie on its own screen, but it cannot make your computer's math give a different result: it committed to the ballot before knowing whether you would test, and the key it printed only opens that ballot.

Do I need to understand cryptography to check?

No. You type the code, see whether the pictures are the same and, if you tested, paste the test text. The answer comes as "your vote is there", "the machine was honest" or "fraud".

Can someone force me to show the receipt to prove my vote?

They can ask, but the receipt proves nothing: the code does not indicate the candidate, and the test is of a cancelled ballot. Anyone trying to buy votes gets no guarantee at all.

What if I lose the receipt?

Your vote is still counted normally. You only lose the ability to check it. The polling station's total remains auditable by anyone.

Is this a blockchain? How does it work if the machine has no internet?

It uses part of blockchain technology: the structure of hash-linked, digitally signed blocks that anyone can download and recompute. It does not use the other part: there is no mining, no cryptocurrency and no network of computers competing to write — only the election authority writes. The machine stays offline all day, as today; at the end it produces a signed file that is taken to the election authority, and only then is it published on the chain. The machine never talks to the chain. Details in section 7.4.

Today the machine shuffles the votes so nobody knows the order. How do I find my vote without undoing that?

You do not find your vote in plain text: you find your encrypted ballot. Each ballot is encrypted with fresh randomness and stored in the order of the ciphertext hash, with no timestamp. The receipt code points to the ciphertext, and the check proves it was included and added up — without opening it. There is nothing to shuffle because no plaintext vote is stored. Details in section 13.1.

What about coerced voting? If I can check my vote, can't someone force me to prove who I voted for?

That is the most important requirement, and the design starts from it. The receipt does not prove the vote: the code does not depend on the candidate, and not even you can open the cast ballot, because its key was destroyed in the machine. The only ballot that can be opened is the TESTAR one, which is cancelled — you can test the candidate the coercer demanded and vote for someone else. Vote buyers and coercers get no guarantee at all. The remaining limits are in section 13.2.

How can this handle 160 million voters without using a country's worth of energy?

The energy use of blockchains comes from mining, which does not exist here: only the election authority writes, and every block is signed. Measured in the prototype, a ballot takes about 12 KB and about 0.1 seconds to audit on one ordinary CPU core. A voter checks only their own polling station; a full national audit fits in a few hundred cores for about a day, using on the order of tens of kWh. Numbers and limits in section 7.5.

What if the polling station has no printer?

The receipt can be delivered as a QR code on the poll worker's terminal screen after the vote. The voter, already outside the booth, photographs the code with their phone. The content is the same as on paper and is signed by the machine, so the terminal cannot alter it without being caught. Anyone without a phone can ask for the printed version.

Does testing the machine slow down the queue?

A few seconds. The test ballot is opened on the spot, and to actually vote you just press CONFIRMA again — no need to retype the number.

Each block contains the hash of the previous one and is signed with the board's Ed25519 key, published in the genesis block. The genesis also publishes the options (with the SHA-256 of each photo) and the hash of the software running at the polling station.

7.4 What the chain of blocks is — and is not

A legitimate question: how do you put a blockchain in a voting machine with no internet? The answer is that the machine does not use the chain during voting. It works offline and, at the end of the day, hands over a signed file (the media, section 7.1). Only afterwards does the election authority publish that file on the chain.

T-VOTE uses part of blockchain technology: the data structure. Records are kept in blocks, each block stores the hash of the previous one and is signed, nothing can be altered or removed without breaking the links and the signatures, and anyone can download the chain and recompute everything. It does not use the other part, decentralized consensus:

FeatureCryptocurrency blockchainT-VOTE chain
Hash-linked blocksYesYes
Digital signaturesYesYes (board, machine and every ballot)
Anyone can download and verifyYesYes
Who writesAny node, by mining or stakeOnly the election authority, with the board key
Mining / consensusProof of work or proof of stakeNone
Currency or tokenYesNo
Network during votingContinuousNone: the machine is offline

Technically, it is an append-only public bulletin board, the same idea as the Certificate Transparency logs used for HTTPS certificates. Security does not come from many computers agreeing, but from the signatures (the election authority cannot alter a polling station without the machine's key) and from public verification. If the election authority showed different chains to different people, it would show up when auditors compare the hash of the last block with each other and with the paper BUs; in a real system, that final hash should be published in several independent places.

The vote cryptography — ElGamal, zero-knowledge proofs, blind signatures (section 8) — does not come from blockchain but from the verifiable-voting literature. Hashes and digital signatures are common to both.

7.5 Scale: 160 million voters

Another legitimate question: how can 160 million records be supported without using a country's worth of energy? The energy use of cryptocurrency blockchains comes from mining, which does not exist here. The real cost is storing and verifying the ballots. Measured in the prototype (scripts/medir-escala.ts), on a polling station of 300 voters with 14 options (12 candidates, blank and null), on an ordinary desktop computer, with the unoptimized JavaScript implementation:

MeasureValue
One ballot (ciphertexts, proofs, credential, signature and seal, as JSON)≈ 11.7 KB
Block of a 300-voter polling station≈ 3.5 MB
Full audit of one ballot≈ 0.1 s per core
Full audit of a 300-voter polling station≈ 31 s per core

Projection for 160 million ballots, one office with 14 options:

  • Storage: about 1.9 TB — it fits on an ordinary disk. A compact binary format would reduce this.
  • Full national audit: about 4,600 core-hours; with 200 cores, roughly one day. Assuming 10 W per core, around 47 kWh — about what a refrigerator uses in a month.
  • Voter check: download only your own polling station (a few MB) and check it in seconds.

A real limit: offices with many candidates. The prototype encrypts one position per option. That works well for offices with few candidates, such as president or governor, but not for congressional deputies, who can number in the hundreds in one state: the ballot would take hundreds of KB per office. A general election also has several offices in the same vote, and each adds size and time. That would require another technique, such as verifiable shuffling (mix-nets), used in other verifiable voting systems, instead of the per-option homomorphic sum.

8. Cryptography

8.1 Primitives

8.2 The ballot

With k options (candidates, blank and null), the ballot encrypts a vector with 1 in the chosen option and 0 in the others. For each option i:

a_i = g^(r_i) b_i = g^(m_i) · h^(r_i) m_i ∈ {0, 1}, Σ m_i = 1

h is the three trustees' joint public key. Each pair (ai, bi) carries a proof that it encrypts 0 or 1, and the ballot carries a proof that the sum encrypts exactly 1 — without revealing which option. The ballot's tracker is the SHA-256 of all the ciphertexts.

The ballot key

Each ballot has a 128-bit seed from the machine's CSPRNG, and all its randomness derives from it:

r_i = H("T-VOTE/aleatoriedade/v1", [seed, election_hash, i]) mod L

For a cast ballot, the seed is destroyed at the moment of casting. For a test ballot, it is revealed, published in the BU and printed on the receipt: with it, any computer redoes the ciphertexts of every possible option and finds out which one was encrypted.

8.3 Anonymous credential

Once released by the poll worker, the machine generates an ephemeral Ed25519 pair and asks the desk terminal for a blind signature over the public key. The desk signs without seeing what it signs and only adds 1 to its counter, which is printed on the BU as turnout. The ballot is signed with this credential, and the nullifier (SHA-256 of the credential key) prevents the same credential from voting twice. Neither the desk nor the roll can link a credential to a voter.

8.4 Seal, code, pictures and check code

As soon as the ballot is sealed, the machine seals it with its own key. The seal is deterministic (Ed25519):

seal = Ed25519(machine_key, SHA-256("T-VOTE/selo/v1|" ‖ {election, tracker, station})) v = SHA-256("T-VOTE/verificacao/v1|" ‖ seal) pictures = PICTURES[v[0]], PICTURES[v[1]] 16 bits (256 pictures) code = zone ‖ station ‖ base32(25 bits of v[2..6]) 25 random bits check code = base32(40 bits of v[6..11]) 40 bits

The code uses Crockford base32 (no I, L, O or U); when reading, O becomes 0 and I/L become 1. It is unique within the polling station, and the station prefix makes it unique within the election. The 256 pictures were chosen to be drawable, with no pairs differing by a single letter and no political, religious or weapon content.

Why the check code exists. The 2 pictures alone have 16 bits: in a trial, a rigged machine found, in fewer than a thousand encryptions, two ballots (one per candidate) with the same pictures — and could open one in the test and cast the other. With code and pictures (41 bits), the same pair would need about 220 encryptions, still within reach of a prepared machine. The check code, printed before the decision, raises the commitment to 81 bits: the same attack then needs about 240 encryptions on the spot, which is infeasible.

8.5 Machine test (Benaloh challenge)

After seeing the commitment, the voter can press TESTAR. The machine reveals the seed, keeps the opened ballot for the BU and signs a declaration with the candidate it says it found and the printed key:

declaration = Ed25519(machine_key, SHA-256("T-VOTE/declaracao-teste/v2|" ‖ {election, station, tracker, option, seed}))

At home, the validator re-encrypts each option with the seed from the paper and looks for the only one that exactly reproduces the ciphertexts sealed under that code. If it is not the declared one, the machine lied, and the signature turns this into transferable proof. If someone alters the paper, the signature stops matching — a forged paper cannot incriminate an honest machine.

8.6 Zero report and results report

Both are canonical JSON documents signed by the machine:

  • Zero report: election, polling station, machine key, desk key, software hash, number of ballots in memory (zero) and opening time.
  • BU: points to the zero report's hash and carries turnout (the desk's counter), all ballots and test ballots in tracker order, the plaintext count per option (what gets printed) and the homomorphic aggregate of the ciphertexts.

The BU code printed on paper is the first 16 hexadecimal characters of the document's hash.

8.7 Per-station tally

The election key is the product of the three trustees' keys. For each polling station s and option j, with aggregate (Asj, Bsj):

D_sj,t = A_sj^(x_t) (with a Chaum-Pedersen proof; context includes the station) g^(m_sj) = B_sj / (D_sj,1 · D_sj,2 · D_sj,3) → m_sj by search in [0, number of ballots]

Before decrypting, each trustee audits the package and recomputes the aggregate; it refuses to decrypt anything that is not the sum it recomputed itself. Decrypting station by station makes it possible to compare each printed BU with the cryptographic tally.

11. Universal audit

The auditor receives only the public package (the chain of blocks) and redoes 22 checks:

  1. Chain integrity (hash and linking of each block)
  2. Board signature on each block
  3. Election manifest (genesis) and protocol version
  4. Order of phases
  5. Trustee keys with Schnorr proof
  6. National zero report and joint key
  7. Machine loading: own key, none repeated, software equal to the genesis, no loading after the media
  8. Media signed by the loaded machine, zero report at zero, one media per station
  9. Ballots without arrival order and without time (exact fields, tracker order)
  10. Valid anonymous credentials from the station's desk
  11. Signature of each ballot
  12. Zero-knowledge proofs
  13. Trackers and nullifiers recomputed
  14. Code, pictures and check code derived from the seal; unique codes
  15. One credential, one vote
  16. Test ballots match the revealed seed
  17. Ballots ≤ turnout; the BU count adds up to the number of ballots
  18. Homomorphic sum per station
  19. Closing lists exactly the stations received and those without media
  20. Each trustee's partial decryption, station by station, with proof
  21. Printed BU = cryptographic tally
  22. Published result = recomputed, per station and in total

Machines with tampered software

Seven lab machines simulate programs swapped before loading. All of them show voters what they typed, all claim the software checks out, and every one's BU passes the mathematical audit — because the machine counts in the BU what it actually encrypted. In every case, the fraud was caught at home:

Math does not see intent. A machine that encrypts the wrong candidate produces a perfectly valid ballot. Only the voter knows what they typed — that is why the test, checked outside the machine, is indispensable, and why the system combines the mathematical audit with the paper and the voter.

13. Secrecy, coercion and the lesson of TPS 2012

In the 2012 Public Security Test (TPS) of the Brazilian voting machine, researchers showed that the order of the votes recorded by the machine of that time could be reconstructed, because the shuffling used a non-cryptographic generator seeded with the time. T-VOTE responds in several layers:

  • There is no shuffle to seed: the BU lists the ballots in tracker order, which is the hash of random ciphertexts.
  • The machine's memory is a table with no sequential identifier, indexed by (machine, tracker): the stored order is the hash order, not the arrival order.
  • No per-vote record with a timestamp; SQLite's journal in DELETE mode and secure_delete erase what could remain.
  • The roll does not record the order of attendance, and the desk signs blindly.
  • The key of each cast ballot no longer exists after casting.

In a statistical test with 160 ballots per candidate, the first picture came out "odd" in 49% of one candidate's ballots and 50% of the other's, as expected from values independent of the vote.

13.1 Shuffling versus encrypting

A legitimate question: if the machine shuffles the votes precisely so that nobody can trace them, how can my vote be linked to the machine afterwards? The current machine stores votes in plain text in its Digital Vote Record (RDV) and shuffles them so that the storage order does not reveal the order of the queue. TPS 2012 showed the risk: if the shuffle is predictable, the order can be reconstructed and, crossed with the voters' arrival order, reveal votes.

T-VOTE stores no plaintext vote, so it does not depend on shuffling:

  • Each ballot is encrypted with fresh randomness; two ballots for the same candidate are indistinguishable.
  • The storage order is the tracker order (hash of the ciphertext): random and unrelated to arrival.
  • The voter finds their ciphertext by the receipt code. That proves it was included and added up, not what it contains.
  • Only each polling station's sum is decrypted (section 8.7).

A consequence worth recording: in a polling station where everyone voted for the same candidate, the result reveals everyone's vote — but that already happens today, because each polling station's BU is public.

13.2 Coercion and vote buying

This is the most important criticism of any verifiable system, and rightly so: in violent regions, if a vote can be proven, voters can be forced to prove it. The required property is called receipt-freeness: the voter cannot prove their own vote to anyone, even if they want to.

What the coercer demandsWhy it does not work
To see the receiptThe code and pictures come from a random ciphertext and do not depend on the candidate.
That the voter open their own vote at homeImpossible: the key of the cast ballot is destroyed in the machine at the moment of voting, and the trustees only decrypt sums.
That the voter test the coercer's candidate and show the testThe test is of a cancelled ballot. The voter can test the coercer's candidate and vote for someone else.
To see the terminal's QR code (section 15)It contains exactly the same as the paper.

What stays the same as the current system, or remains open:

  • A photo or video of the screen inside the booth: beyond the reach of cryptography, as today; the law forbids phones in the booth.
  • A rigged machine leaking the vote through the pictures (subliminal channel, section 14): the voter cannot control this; mitigation is future work.
  • Coercion not to vote and very small polling stations: the same as the current system.

In short, T-VOTE does not make coerced voting easier than it is today: what the voter takes home is not proof for anyone. If someone finds a way for a voter to prove their own vote with what they take home, that is a serious flaw and should be reported.

14. Limits and future work

Saying what is not solved is part of security.

  • Secrecy against a rigged machine. The machine sees the vote, like today's. If rigged, it can choose the randomness so that the pictures "encode" the candidate — a subliminal channel demonstrated in the lab (20 out of 20 votes leaked with at most a few dozen encryptions per vote). Integrity does not depend on trusting the machine; secrecy against it does. Future work: randomness from a second independent device, with re-encryption before the seal.
  • An insider with the machine and desk keys can fabricate a mathematically perfect polling station. Those who catch it are the voters and the paper BU; that is why paper and observers' photos remain essential.
  • Clash attack between voters: a rigged machine could show two voters the same ballot. Each one, in isolation, finds "their" code; it is only caught by comparing receipts.
  • The test is probabilistic and depends on how many voters test.
  • Three out of three trustees. In production: a t-of-n threshold with distributed key generation.
  • RSA-FDH for credentials. In production: standardized blind signatures (RFC 9474).
  • Keys in software. In production: hardware modules (HSM/TPM), measured boot and reproducible builds.
  • In-person coercion (someone inside the booth, a photo of the screen) is beyond the reach of cryptography.
  • Code not audited by third parties.
  • Offices with many candidates (deputies): a ballot with one ciphertext per option gets large; verifiable shuffling (mix-nets) would be needed. See section 7.5.

15. Deployment without printers: receipt by QR code

A thermal printer in every machine (plus the paper, maintenance and logistics) is the most expensive item in this design. To start without that cost, the receipt can be delivered digitally, on the poll worker's terminal, after voting:

  1. The voter votes (and, if they wish, tests) on the machine, as described above. The machine shows the pictures, the code and the check code on its own screen, as always.
  2. When the voter confirms, the machine sends the receipt to the poll worker's terminal over the same local channel it already uses for the release, without internet.
  3. The voter leaves the booth and the terminal shows a QR code with the receipt, in an area of the screen facing them. They photograph the code with their phone, and the screen is cleared as soon as the next voter is released.
  4. At home, the verification page or the offline validator reads the QR code and does the same checks as with paper: vote, test and BU.

What goes inside the QR code

Exactly what the paper carries: vote code, check code, picture names and the machine's signature on the receipt. For each test, the declared candidate, the code, the test ballot key and the signed declaration. With one or two test ballots this is a few hundred characters, which fits in a medium-sized QR code that is easy to read from a screen. If the code is an address of the verification page, the data must go after the # (the URL fragment), which the browser does not send to the server: 

https://<verification page>/verificar#v=1&c=0100123WGFTT&k=9RD2RJJP&s=…&t=…

Why on the poll worker's terminal and not in the booth

  • The law forbids phones in the booth. Brazilian Law 9,504/1997, art. 91-A, sole paragraph, forbids carrying phones and cameras into the voting booth. With the QR code on the terminal, the voter only uses the phone after leaving.
  • The terminal already exists. No new hardware, only software. Deployment cost is close to zero.
  • Paper is still possible. Both forms can coexist: QR code by default and paper for anyone who asks or has no phone. This allows a gradual transition, station by station.

What changes for security

PointAnalysis
Could the poll worker's terminal show a fake QR code?Not without being caught. The receipt and the test declaration are signed by the machine, with the key published at loading, and the validator checks those signatures. An altered or swapped code does not match: the pictures differ from the ones the machine showed on its screen, or the signature fails.
Does the poll worker see the receipt?They may, and it does not reveal the vote: the code and pictures do not depend on the candidate. The test part shows the tested candidate, which belongs to a cancelled ballot. For discretion, the QR code sits in an area facing the voter and disappears with the next release.
What if the terminal does not show the QR code?The voter only loses the later check. The vote has already been cast and counted. A systematic refusal to deliver receipts is visible and can be recorded by observers.
Anchor against a rigged machineIt is still what the machine showed on its own screen, before the decision: the 2 pictures, the code and the check code. The voter checks that the QR code carries the same values. This keeps the 81-bit commitment of section 8.4.
Vote sellingSame as paper: the QR code does not prove who the person voted for.
InclusionNot every voter has a phone with a camera. That is why printing on demand should remain available, even if with only a few printers per voting location.

Not yet in the prototype. Today the prototype prints the receipt on paper (simulated on screen). The QR code on the poll worker's terminal is the proposal for the first deployment phase. The cryptography does not change: only the way the receipt is delivered.

16. How to reproduce

The prototype runs on a single computer, with no internet access during execution. Code: github.com/tauz-hub/T-VOTE.

Requirement: Node.js 22 or newer. The INICIAR.bat and iniciar.sh launchers download Node.js automatically if it is missing (see Code and download).

git clone https://github.com/tauz-hub/T-VOTE.git
cd T-VOTE
npm install
npm run dev               # http://127.0.0.1:3000
npm run teste             # in-memory protocol: auditor, test redone at home and 14 attacks
npm run teste:invasao     # full election through the real modules + penetration report
npm run validador         # builds the offline validator (a single HTML file)
npm run auditar -- pacote.json
npm run verificar -- pacote.json <code> ["test key"]
npm run verificar -- pacote.json --bu 010-0123

Demo walkthrough

  1. Admin → Election: create the election (candidates can be edited).
  2. Trustees: generate the three keys; then, in Admin, Open election.
  3. Registry: generate fictitious voters.
  4. Poll worker: open the terminal and the machine in separate windows. On the machine, install with the keypad (zone and station) and press CONFIRMA for loading. On the terminal, open the station.
  5. Vote: release a voter, type a number, press TESTAR and then CONFIRMA; keep the receipt.
  6. Close: close the station (BU) and transmit the media; in Admin, stop receiving; in Trustees, decrypt.
  7. At home: Check vote (code), Check test (paste the receipt), Polling station report and Audit.
  8. Frauds: Admin → Attack lab → Create the 7 sample machines → Simulate all and transmit → Check at home.

So as not to depend on the validator file you downloaded, rebuild it from the source code and compare the SHA-256: the build is deterministic. The full specification — formats, hash domains, checks and API — comes with the code, and an independent implementation (in Python, for example) must accept the prototype's packages and reject the same tamperings.
